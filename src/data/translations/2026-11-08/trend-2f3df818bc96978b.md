GitLab 블로그 글(빌 스테이플스, 2026년 10월 13일) 앞부분을 읽고 옮겼어요.

### 에이전트가 바꾼 소프트웨어 경제학

AI 에이전트가 소프트웨어 개발의 경제학을 근본적으로 바꾸고 있어요. 코드를 만드는 비용이 떨어지면서 소프트웨어 팩토리를 지나는 변경량이, 사람 개발자용으로 설계된 인프라가 감당할 수준을 넘어 빨라지고 있다는 거예요.

GitLab은 이 변화를 예상하고 대형 저장소에서 수천 개 에이전트가 동시에 일할 수 있는 차세대 SCM을 개발하기 시작했어요. 6월 GitLab Transcend에서 Anthropic 소스 관리팀의 Nick G.와 함께 발표했고, 8월에는 아키텍처와 초기 성능 결과를 더 공유했어요.

### Anthropic의 Scion 사례

이번 주 Anthropic은 이 작업이 왜 중요한지 보여 줬어요. 모노레포의 일일 머지가 5월 약 2,500건에서 9월 3만 건 이상으로 늘자, 엔지니어들이 자기 환경에 맞춘 전용 소스 관리 시스템 Scion을 만들었어요. Scion은 거의 모든 클라이언트가 항상 온라인인 에이전트인 거대 모노레포용이고, Anthropic도 범용 Git 대체재가 아니며 자체 코드 리뷰·검색·CI 인프라가 필요하다고 인정했어요. GitLab은 더 넓은 기업 시장을 위해 Git 호환성, 인프라 선택권, 개발 수명주기 통합을 지키면서 에이전트 규모 성능을 내겠다고 해요.

> "에이전트 개발을 위해 모노레포를 확장하면서 Git 서버 아키텍처에 대한 생각이 바뀌었어요. 전체 Git 모델을 벗어나지 않고도 이런 워크로드를 위해 Git 서버가 할 수 있는 일을 넓힐 여지가 있다고 봐요." — Nick G.(Anthropic 소스 관리)

### Git 위에, 에이전트를 위해

전통적인 Git 워크플로는 에이전트가 일부만 필요해도 상당한 저장소 데이터를 내려받게 해요. 에이전트 호출 한 번에 질문 하나에 답하려고 5~10GB 전송과 30초 넘는 준비가 들 수 있고, 수천 개 에이전트로 곱하면 소스 관리가 병목이 돼요.

- 차세대 SCM은 Git 프로토콜을 유지하면서 아래 아키텍처를 현대화해요.
- 상태 없는(stateless) 컴퓨트가 공유 객체 스토리지 위에서 수평 확장하고, 에이전트 네이티브 인터페이스로 저장소 전체를 반복 clone하지 않고 필요한 파일과 히스토리만 요청해요.
- 초기 내부 테스트에서 기존 워크플로 대비 작업이 최대 50배 빠르고, 토큰은 최대 2배 적게, 네트워크 트래픽은 최대 1,000배 적게 썼어요. GitLab은 특정 조건의 최대치이며 지속적인 동시 부하 성능은 계속 검증 중이라고 밝혀요.
- 같은 아키텍처가 GitLab.com과 고객이 관리하는 S3 호환 스토리지(에어갭 데이터센터 포함)에서 돌도록 설계돼, 저장소 데이터가 고객 인프라 안에 머물러요.
