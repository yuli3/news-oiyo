링크된 GitHub 폴더에는 한 줄짜리 README뿐이라, 실험 설명은 작성자가 r/LocalLLaMA에 올린 글(RSS 본문)을 기준으로 옮겼어요.

### 발단

작성자는 KV 캐시·temperature 0·재현성 논쟁 이후 Ollama와 llama.cpp에서 모델이 어떻게 동작하는지 조사하다 예상하지 못한 걸 발견했어요. GGUF에 저장된 Bielik-Minitron 7B 채팅 템플릿에는 시퀀스 시작(BOS) 토큰이 있는데, Ollama가 이 모델에 쓰는 템플릿은 그걸 넣지 않는다는 점이에요. "토큰 하나일 뿐"이라고 생각했지만 실제로 뭔가 바뀌는지 확인해 봤어요.

### 실험 조건

- 모델: Bielik-Minitron 7B v3.0 Instruct, Q4_K_M
- 엔진: Ollama 0.40.14, Arch Linux
- temperature 0, seed 42, 컨텍스트 2048토큰
- 폴란드어, JSON, Python을 다루는 15개 과제
- 세 변형: **Template**(Ollama 채팅 템플릿 그대로), **Raw**(템플릿과 같은 수동 프롬프트, BOS 없음), **Raw + BOS**(같은 프롬프트 앞에 BOS 추가)
- 변형마다 3회 반복해 총 135회 시행. 매번 모델을 메모리에서 내리고 캐시에서 재사용한 토큰이 0이 되게 해 BOS 하나만 변수로 남겼어요.

### 결과

Template과 Raw는 15개 과제 모두 같은 응답을 냈어요. BOS를 넣자 **15개 중 6개 응답이 바뀌었어요**.

- 폴란드어 발음 구별 기호: 틀린 철자 → 올바른 "Zażółć gęślą jaźń", 통과 0/3 → 3/3
- 호격, 동사 상: 마침표 유무 정도만 바뀌고 3/3 유지
- Henryków 문장: 긴 설명 → 짧은 설명, 0/3 유지
- 하드웨어 JSON: Markdown 코드 블록 안 JSON → 코드 블록 없는 JSON, 3/3 유지
- 피보나치: for 루프 → while 루프, 3/3 유지
- 나머지 9개: 변화 없음

각 변형의 3회 반복은 모두 같은 응답을 냈고, BOS는 모든 과제에서 프롬프트 길이를 정확히 1토큰 늘렸어요(예: 64 → 65토큰).
