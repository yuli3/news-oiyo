원문(Apiiro 블로그)이 Cloudflare 보안 확인 페이지만 보여 줘 읽지 못했어요(직접 요청 403, Wayback 429). 그래서 제목과 Hacker News 토론에서 확인되는 내용만 정리했고, 원문의 세부 수치와 방법론은 확인하지 못했어요.

### 제목이 말하는 것

제목은 Claude Code의 "Don't Ask Again(다시 묻지 않기)" 기능 때문에 공개 GitHub 파일 1,122개에서 비밀번호가 노출됐다고 말해요.

### HN 토론에서 정리된 노출 경로

- 한 HN 사용자는 제목이 헷갈린다며 이렇게 정리했어요. 조사팀은 사람들이 `.claude/` 폴더와 로컬 설정을 커밋한 저장소를 찾은 뒤, 그 파일들에서 키나 비밀번호가 담긴 명령을 찾아냈다는 거예요.
- 즉 "다시 묻지 않기"를 누르는 것만으로 비밀번호가 노출되는 건 아니에요. 비밀값이 명령에 직접 들어간 상태로 수동 승인하고, 그 로컬 설정을 커밋해 저장소를 공개했을 때 노출돼요.
- 원문은 조직 저장소에서 `.claude/settings.local.json`과 `.claude/settings.json`을 검색해 보라고 권한 것으로 인용됐어요. 다만 실제 공개 여부는 저장소 설정에 달려 있다는 지적도 있었어요.
- 조사 측으로 보이는 사용자는, 파일이 프로젝트 안에 생기지만 전역 gitignore에만 추가돼 새로 클론하거나 다른 머신에서는 일반 파일처럼 커밋될 수 있다고 설명했어요. 추적한 1,105개 저장소 중 539개에서 Claude가 공동 작성한 커밋이 이 파일을 바꿨다고 해요.

### Claude Code 팀의 답

Claude Code 팀의 Boris라고 밝힌 사용자는, Claude Code가 그동안 비밀값 제거(secret scrubbing)를 하지 않았지만 이를 막을 방법을 살펴보고 있다고 답했어요. 또 `.claude/settings.local.json`은 로컬에만 두는 파일이라 소스 관리에 넣으면 안 되고, Claude가 파일을 만들 때 자동으로 gitignore한다고 덧붙였어요.

### 토론의 다른 반응

- 비밀값을 커밋한 사용자의 책임이고 오픈소스 하네스에서도 같은 일이 생길 수 있다는 반론이 있었어요.
- 비밀값을 패스워드 매니저에 두고 필요할 때 CLI와 지문 인증으로 꺼내 쓴다는 대안도 공유됐어요.
