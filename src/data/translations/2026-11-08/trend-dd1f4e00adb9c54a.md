Entire의 발표문(2026년 7월 8일자) 앞부분을 읽고 옮겼어요.

### 에이전트 규모 개발을 위한 버전 관리

개발자 도구 역사상 최대 시드 라운드 이후 5개월 만에, Entire가 분산 Git 네트워크 프리뷰를 내놨어요. 개발자는 저장소를 하나의 중앙 제공자가 아니라 전 세계에 호스팅할 수 있어요.

- 현재 대기자 명단으로 열려 있고, 미국·EU·호주 리전이 활성화돼 있어요.
- 기존 GitHub 저장소를 한 번에 Entire로 미러링해요. 코드는 원래 자리에 두고, 에이전트는 지역 Entire 미러에서 clone·pull해요.
- 무겁고 동시다발적인 읽기 트래픽을 덜어 에이전트가 레이트 리밋 없이 빌드할 수 있어요.
- 앞으로 몇 달 안에 공개·비공개 저장소의 네이티브 호스팅을 열고, 네트워크를 완전히 탈중앙화해 어느 리전에서든 데이터 레지던시·주권·확장을 지원할 계획이에요.

### 벤치마크

Entire는 동시·대량 에이전트 활동을 감당하도록 Git 백엔드를 다시 만들었고, 초기 테스트에서 Cursor Origin 같은 경쟁 서비스보다 최대 25배 좋은 결과를 냈다고 밝혀요.

- **Git Clone**: 단일 저장소에서 시간당 약 57만 회 clone을 유지했어요(프랑크푸르트 40%, 파리·런던·더블린의 200개 가상 클라이언트가 약 3분간 shallow clone).
- **Git Push**: 단일 저장소·브랜치에 초당 586회(시간당 약 210만 회) push를 유지했어요(128개 가상 에이전트가 2분간 push당 2KB 파일 1~10개를 각자 브랜치에, Entire 네이티브 저장소 기준).
- **Clone + Push 혼합**: 에이전트가 실제로 도는 방식대로 shallow clone → push 5회 → 반복을 128개 에이전트가 돌렸을 때 단일 저장소에서 초당 약 470회, p50 지연 약 50~60ms였어요.

Entire는 벤치마크 스위트와 함께 Git 백엔드를 오픈소스로 공개할 예정이에요.

### CEO 발언

> "Git은 원래 분산되도록 설계됐어요. 리누스 토르발스가 2007년 구글 테크토크에서 말했듯 '분산되지 않으면 쓸 가치가 없어요.' 에이전트 시대에 중앙집중식 Git 호스팅은 근본적인 제약이 됐어요. 수십억 에이전트와 개발자가 중앙 서버를 두드리는 부담이 레이트 리밋, 높은 지연, 심지어 장애로 나타나요." — 토마스 돔케(Entire CEO)
