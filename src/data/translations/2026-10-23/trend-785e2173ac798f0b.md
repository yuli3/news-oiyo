### OpenShell이 뭔가요

OpenShell은 **자율 AI 에이전트 무리(fleet)를 위한 안전하고 비공개적인 런타임**이에요. 에이전트는 파일을 읽고, 패키지를 설치하고, API를 부르고, 자격 증명을 쓸 수 있을 때 가장 쓸모가 있어요. OpenShell은 이런 능력을 주되 데이터·시크릿·네트워크에 대한 무제한 접근은 주지 않아요. 각 에이전트가 무엇을 건드릴 수 있는지 **정책(policy)**으로 선언하면 OpenShell이 그걸 강제해요.

0.1.x부터는 안정적인 릴리스 주기, 새 격리 프리미티브, 확장 지점, 새 API가 들어갔다고 해요(0.1.0 업그레이드 가이드 별도).

### 동작 방식: 두 가지 축

1. **커널 수준 강제**
   - 에이전트마다 격리된 샌드박스에서 돌아가요.
   - 커널 제어로 접근 가능한 파일과 호출 가능한 시스템 콜을 제한해요.
   - 모든 네트워크 연결은 샌드박스를 떠나기 전에 정책 검사를 거쳐요.
   - 에이전트는 **실제 자격 증명을 보지 못해요.** OpenShell이 승인된 엔드포인트로 가는 요청에만 자격 증명을 덧붙여요.
2. **형식 검증된 정책 변경**
   - 정책 변경을 승인하기 전에 형식 검증(formal verification)으로 그 변경이 새로 허용하게 될 위험한 접근을 표시해요. 예를 들어 자격 증명을 들고 새 호스트에 접근하거나 새 API 메서드를 부르는 경우예요.
   - 이런 변경은 사람의 검토를 기다리게 돼요.

게이트웨이, 슈퍼바이저, 샌드박스가 어떻게 맞물리는지는 Architecture 문서에 있다고 해요.

### 빠른 시작

Linux, Apple Silicon macOS, 또는 WSL 2가 있는 Windows(실험적)에 Docker·Podman이나 호스트 가상화가 필요해요.

```sh
curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh
openshell sandbox create --name demo
```

설치 스크립트가 CLI와 로컬 게이트웨이를 깔아요. 기본 샌드박스 이미지는 에이전트가 없는 최소 Ubuntu예요. "Run Your First Agent" 튜토리얼은 무료 OpenRouter 모델로 OpenCode를 돌리면서, 에이전트가 필요로 할 때 새 접근을 승인하는 흐름을 보여 줘요.

### 더 볼 것

- **Sandboxes**: 이미지, 런타임, GPU, 수명 주기
- **Policies**: 파일 시스템·네트워크·프로세스 규칙, 변경 검토용 advisor와 prover
- **Providers**: 승인된 엔드포인트에서만 작동하는 자격 증명(추론 포함)
- **Gateways**: 샌드박스·정책·접근의 컨트롤 플레인
- **Kubernetes**: Helm으로 게이트웨이 배포(CNI가 NetworkPolicy를 강제해야 해요)
- **Extensibility**: 미들웨어, 인터셉터, 컴퓨트 드라이버

### 에이전트 스킬과 SDK

`npx skills add NVIDIA/OpenShell`로 코딩 에이전트용 공개 스킬을 설치할 수 있어요. 이 스킬은 에이전트에게 OpenShell CLI 조작, 샌드박스 정책 작성, 게이트웨이·추론 라우팅 디버깅을 가르쳐요. SDK는 Python(`uv add openshell`), TypeScript(`@nvidia/openshell-sdk`), Go, Rust로 나와 있고, CLI를 설치하지는 않아요. 가능하면 SDK와 게이트웨이를 같은 릴리스로 맞추라고 권해요.

프로젝트는 자신이 가능하게 하는 것과 같은 에이전트 주도 워크플로로 개발된다고 밝혀요.
