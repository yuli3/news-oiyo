### 개요

작성자(hiImMate)는 한 달 전 소개한 프로젝트를 완성해 **무료 게임**으로 냈어요(itch.io의 Hyper Clashers). 궁금했던 건 "Qwen 3.8 Flash Next(3.8FN)가 게임 개발을 얼마나 잘하나"였어요. 게임 코드는 **100% Qwen 3.8FN**이 썼고 프런티어 모델 도움은 받지 않았다고 해요. 디버깅을 Opus 5.5로 빨리 끝내고 싶은 유혹도 있었지만 참았대요.

### 환경

- 모델: Qwen 3.8 Flash Next, Unsloth UD_Q4_XL 양자화(업데이트 전)
- 장비: Strix Halo(Ryzen AI 395+, Bosgame M5), Windows
- 추론 엔진: 직접 만든 Windows용 Gufo 포크(llama 속도는 너무 느리다고 해요)
- 하네스: 직접 만든 평범한 하네스(공개 계획 없음)
- 기술 스택: TypeScript + three.js
- 통계: 프롬프트 1,911번, 도구 호출 31,883번, 출력 토큰 약 2,037만 개, 입력 토큰 약 30.7억 개(그중 약 30.4억 개 캐시)

### 모델 평가

돌릴 수 있다면 "지금 돌릴 수 있는 최고의 모델"이라고 해요. 3.8 27B나 3.6 35B로는 완성품까지 못 갈 것 같았는데, Flash Next는 코딩이라면 거의 다 풀어 줬다는 거예요. 다만 3D 작업용은 아니라고 해요.

### 잘 통한 방법

- 막히면 **코드를 그대로 붙여 달라고** 했더니 약 70%는 그 과정에서 모델이 스스로 버그를 찾았어요.
- **측정·검증·헤드리스 실행**을 시켜요. 코드에서 추론하지 말고 스크립트와 디버그 출력으로 숫자를 보게 해요.
- 키보드로 켜는 **사람용 로깅 도구**를 만들어 버그를 재현하고 숫자만 넘겼어요.
- **범위를 분명히** 정해요. 모호하면 모델이 선을 넘어 더 많이 해요.
- 자율 실행은 **측정 가능한 일**에만 맡겼어요. 게임 속 AI는 파라미터 1만 개짜리 작은 신경망인데, 30분 학습 → 미리 정한 벤치마크로 체크포인트 비교 → 숫자로만 다음 체크포인트 선택을 반복하게 했어요.
- **preserve thinking**을 켜자 속도가 크게 올랐어요.
- 컴팩션 대신 **.md 문서**로 지식을 넘겼어요. 매 턴 미리 채우는 파일은 끝까지 1만 토큰 정도였어요.
- 모델 편집기, 트랙 편집기, AI 학습 대시보드 같은 **도구를 직접 만들게** 했어요.
- 로컬 **git**은 필수예요.

### 말리는 것

**결정을 AI에 맡기지 말라**고 해요. 모델은 교과서 지식은 다 있지만 남이 원하는 걸 잘 모르고 지름길을 택하는 주니어 같다는 거예요. 너무 큰 작업을 주면 물리 시뮬레이션을 다 안 만들거나 합의한 구조를 어기는 식으로 거의 확실히 지름길을 택하니, 늘 지켜봐야 한다고 해요.
