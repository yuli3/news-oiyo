AI타임스 기사 전문을 읽고 정리했어요. 한국어 기사라 번역 대신 요지를 옮겼어요.

### 무엇을 공개했나
앤트로픽은 2일(현지시간) AI 추론 결과의 신뢰성을 검증하는 시스템 **FlashProve**를 공개했어요. 영지식 증명의 한 종류인 **zkSNARK**를 써서, 모델 내부 가중치를 드러내지 않고도 어떤 응답이 지정된 모델의 계산 결과인지 확인해요.

### 왜 필요한가
지금은 AI 서비스에 질문을 보내도 실제로 어떤 모델이 답했는지 이용자가 직접 확인하기 어려워요. 서비스 업체가 비용을 아끼려고 싼 모델로 바꾸거나 성능 평가 때만 다른 모델을 써도 출력만으로는 구분하기 힘들어요.

### 작동 방식
1. 서비스 업체가 특정 모델 가중치에 연결된 일종의 **디지털 지문**을 먼저 공개해요.
2. 이용자 입력에 대해 그 모델이 응답을 만들었다는 **암호학적 증명 파일**을 생성해요.
3. 이용자는 지문, 입력, 응답, 증명 파일을 대조해 확인해요.

가중치와 중간 계산값은 숨기지만 모델 구조까지 비공개로 두지는 않아요. 검증 대상은 답의 사실성이나 품질이 아니라 지정한 모델의 계산 결과와 일치하는지예요. 모델이 틀린 정보를 냈다면 증명이 유효해도 내용이 사실이라는 보장은 없어요.

### Claude의 역할
개발 과정에서 Claude가 기존 암호학 연구 도구를 새로 적용해 증명 시스템의 계산 효율을 높였어요. 앤트로픽은 Claude가 쓴 프로토콜 명세도 공개했는데, 연구진이 세부까지 검토하지는 않았다며 직접 쓴 기술 보고서와 구분했어요.

### 성능과 한계
- 총 4,000억 파라미터 MoE 모델 Llama 4 Maverick(4비트 가중치, 정수 연산)으로 시험했고, H100 한 대로 증명을 만들었어요. 요청당 증명 파일은 약 19MB, 검증은 CPU 24스레드로 약 17초 걸렸어요.
- 증명 생성 부담은 커서, 특정 조건에서 vLLM 일반 프리필 대비 GPU 시간이 70~95배였어요.
- 현재 구현은 1,024토큰 문맥 등 제한된 조건이라 상용 서비스에 바로 쓸 완성품은 아니에요.
- 정형 검증 언어 Lean으로 프로토콜의 정확성과 보안 속성을 검증했지만, 실행 코드 전체의 정확성까지 증명한 건 아니고 배치 처리의 영지식 속성도 아직 정형 증명 전이에요.
- 응답을 먼저 주고 별도 서버에서 증명을 만드는 구조라, 조작된 응답 전달을 막기보다 사후 확인에 쓰여요.

앤트로픽은 유료 서비스가 약속한 모델을 썼는지, 외부 평가기관이 시험한 모델과 실제 서비스 모델이 같은지 확인하는 데 쓸 수 있다고 했어요. 기술 보고서, 증명 생성·검증 코드, Lean 증명 자료는 GitHub에 Apache 2.0으로 공개했어요.
