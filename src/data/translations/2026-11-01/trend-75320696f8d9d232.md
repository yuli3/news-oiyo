### 풀려는 문제

픽셀에만 의존하는 컴퓨터 사용 에이전트(CUA)는 비용이 커요. 스크린샷 한 장이 수천 토큰을 먹고, 구조화된 파일 편집을 수십 번의 마우스 클릭으로 다시 하면 가장 빠르고 검증하기 쉬운 경로를 버리게 돼요. 반대로 최첨단 모델에 GUI와 터미널 도구를 그냥 주기만 해서는 둘을 잘 섞어 쓰지 못하고, 그 나쁜 습관이 증류된 학생 모델로 그대로 옮겨진다고 해요.

### Mage-VL-Cowork

- 중간 단계 **4B Mage-VL** 체크포인트에서 시작해 **5단계 '전문화 후 통합' 커리큘럼**으로 끝까지 학습했어요. 스크린샷 기반 GUI 조작(`computer_use`)과 지속되는 코드·터미널 실행(`bash`)을 외부 오케스트레이터 없이 **하나의 비전-언어 정책**에 담았어요.
- 학습 전에 교사 하네스를 **진화**시켰어요. `xdotool`, 접근성 트리처럼 겹치는 도구를 빼고 도메인 Python 라이브러리를 미리 깔자 GPT-5.4 교사가 92.0%를 내며 스텝이 29.2% 줄었고, 4B 학생은 **+12.5%p**(25.1% → 37.6%) 올랐어요.
- 워크플로 우선 합성 엔진 **Mage-CUA-Forge**로 6,915개 원자 기술에 걸친 **293,806개 과제**를 만들었어요. 과제당 토큰을 93.3%(1,276K → 85K) 줄여 비용이 과제당 0.906달러에서 0.158달러로 내려갔어요.

### 성능 (자체 발표)

- 50스텝 예산에서 **OSWorld-Verified 66.0%**로 4B 모델 중 최고예요. 운영체제 과제 87.5%, 다중 앱 워크플로 62.7%예요.
- 시각 grounding은 OSWorld-G 30.6% → 56.9%, ScreenSpot-v2 78.8% → 87.2%로 올랐고, 전체는 45.56% → 55.84% → 66.0%로 단계마다 올랐어요.
- 검증 가능한 보상을 쓴 온라인 GRPO가 Hybrid SFT 대비 **+10.16%p**를 더하면서 모델 호출을 21.57회 → 18.77회(−13.0%), 출력 토큰을 7,374 → 5,499(−25.4%)로 줄였어요.

### 모델 개요

- 구조: `llava_onevision2`(이미지+텍스트 → 텍스트), Mage-ViT + Qwen3-4B(Qwen3-4B-Instruct-2507) 백본, bfloat16 9.48GB.
- 컨텍스트: 학습·추론 32,768토큰(구조상 262,144까지).
- 작업 기억: 최근 스크린샷 3장 + 응답 4개 + 접은 행동 기록.
- 정책이 화면 배치, 캔버스 편집, 실행 중인 앱 상태엔 `computer_use`를, 스프레드시트·문서·프레젠테이션 편집과 결정적 검증엔 `bash`를 스스로 골라요.
