nullprogram.com 글(2026-10-31) 앞부분부터 "Never wait forever" 절까지 읽고 옮겼어요. 뒷부분은 읽지 못했어요.

### 왜 만들었나

필자는 몇 년째 로컬 LLM에 빠져 있어요. 좋은 오픈 웨이트 모델은 이제 고급 소비자 하드웨어에서도 견딜 만한 속도로 돌고, 간단한 프로그래밍 작업은 믿고 맡길 만해졌어요. 그런데 올해 나온 코딩 하네스는 모두 실망스러웠대요. 대부분 웹 스택으로 만들어져 메모리를 엄청 먹어요. 필자 말로 코딩 하네스는 본질적으로 **`popen()`에 붙인 curl**인데, 기가바이트 RAM이 필요할 이유가 없다는 거예요. 그래서 C++와 Dear ImGui 도킹 UI로 **Prospero**를 만들었고, 기능을 덜어내지 않고도 자원을 약 **두 자릿수 배 적게** 써요.

모델 제공자는 내장돼 있지 않아요. llama.cpp, 사내 온프렘 모델, OpenRouter, Anthropic API, OpenAI API 등을 직접 붙여요(Claude 구독은 쓸 수 없어요).

### 기능

- 에이전트가 **하위 에이전트**를 띄워 병렬로 일하거나 컨텍스트를 깨끗하게 유지할 수 있고, 에이전트끼리 메시지를 주고받아요.
- SSH나 WSL로 다른 기계에 **헤드리스 사본을 배포**해 그 시스템에서 에이전트가 일하게 할 수 있어요. Professional Edition은 macOS·Windows·Linux의 x86/x86-64·ARM64 엔진을 내장하고, Windows x86 엔진은 Windows XP에서도 돌아요.
- **데스크톱 제어**도 돼요. 비전을 지원하는 모델이면 화면을 보고 클릭, 입력, 드래그로 GUI 앱을 앱별 MCP 없이 실시간으로 테스트할 수 있어요.
- 헤드리스 엔진 구조라 TUI가 필요 없어요. 엔진은 원격에서 돌고 UI는 내 PC에서 돌며, 설정하면 GUI가 떨어져도 계속 돌다가 나중에 다시 붙을 수 있어요.
- 가벼워서 헤드리스 시스템에서 **퍼징 캠페인**도 돌릴 수 있어요. 다른 하네스는 메모리를 많이 먹어 리눅스 OOM killer가 퍼징 대상 대신 하네스를 죽이곤 했대요. 에이전트가 찾은 버그를 바로 고치며 캠페인을 이어 갈 수 있다는 게 장점이에요.

### 설정

설정은 `~/.config/prospero/prospero.ini`예요. JSON이 아니라 INI라 손으로 고치고 버전 관리하기 쉽고, GUI 설정 페이지로도 다 바꿀 수 있어요. `include = https://...`로 URL의 설정을 포함할 수 있지만, 셸 명령에 들어갈 수 있는 값은 못 바꾸게 제한해요. 그래도 설정이 환경 변수를 API 키로 써서 자기 엔드포인트로 보낼 수 있으니 어느 정도 신뢰는 필요하다고 적어요.

### 설계 원칙

- **수동 렌더링**: 게임처럼 vsync마다 다시 그리지 않고, 애니메이션을 마무리하는 settle 프레임 뒤 쉬어요. 에이전트가 빌드를 기다리는 동안 GPU를 쓰지 않아요.
- **절대 무한 대기하지 않기**: 모든 작업에 마감 시간이 있어요. 권한 요청에 아무도 답하지 않으면 시간 초과로 거부되고 에이전트는 그 없이 진행해요. 주의가 필요하면 시스템 토스트를 띄워요. 네트워크 요청에는 타임아웃, 감시 타이머가 있고 에이전트 메일함은 크기가 정해져 있어요. 시간을 넘긴 셸 명령은 비동기 백그라운드 명령으로 바뀌어 에이전트가 주기적으로 깨어나 계속할지 판단해요.
