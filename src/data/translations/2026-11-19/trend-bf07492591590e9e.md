### Jalapeño 연산 블록

8월에 오픈AI 엔지니어가 프런티어 모델로 첫 커스텀 추론 칩 Jalapeño 개발을 가속했다고 이미 공유한 바 있고, 이번 글은 그 이득 뒤의 설계 개선과, 같은 접근을 AMD의 서드파티 하드웨어에 적용한 결과를 더 자세히 본다고 해요.

Jalapeño 설계에는 2025년 초 GPT-o3 mini부터 쓰기 시작했어요. 초기 모델도  nontrivial한 PPA 개선을 찾았다고 해요.

- 벡터 유닛(병렬 연산을 관리·실행): 부동소수점 가산기·곱셈기, 변환 함수, 리덕션 로직, 특수 기능 유닛에서 절감이 나왔어요. 모델은 다른 논리 구현과 파이프라인 단계 분할을 탐색해 하드웨어를 공유하고 중간 저장을 줄일 기회를 찾았다고 해요.
- 행렬 유닛: 부동소수점 가산기·곱셈기, 저정밀 내적 회로에서 개선이 쌓였어요. 한 곱셈기 재설계는 합성에서 셀 면적을 약 15% 줄이면서 지연을 두 클록에서 한 클록으로 줄였어요. 별도 가산기 재설계는 2사이클 지연을 유지한 채 셀 면적을 약 15% 줄였어요. 내적 로직과 파이프라인 구성의 추가 개선도 블록 전반의 절감에 보탰다고 해요.

더 넓은 Jalapeño 설계에서 팀이 추정하기로는, 모델이 제안한 변경이 벡터 유닛 표준셀 면적을 약 13%, 행렬 유닛을 약 10% 줄였어요. 이 최적화는 Jalapeño 실리콘 bring-up에서 실리콘으로 입증됐다고 해요.

### AMD와의 협력

AMD와 PPA 개선으로 협력해, 플래그십 GPU IP의 이미 많이 최적화된 기준 대비 최대 14% 개선을 봤다고 해요. 모델이 칩 회로를 기술하는 코드(SystemVerilog RTL)를 다시 써서 추가 개선을 찾았고, 이는 대략 1년치 진전을 5개월이 안 되어 이룬 결과라고 적었어요. AMD는 이미 일부 변경을 최근 제조로 보낸 설계에 넣었고, 다른 변경은 이후 버전에 쓰려고 생산 설계 파일에 추가했다고 해요.

모델은 전문가급 마이크로아키텍트 수준으로 RTL을 추론하며, 계산·제어·데이터 이동 회로를 다시 쓸 수 있다고 해요. 각 재작성이 블록 동작을 보존하는지, 전력·성능·면적 트레이드오프는 어떤지를 시놉시스 도구로 검증했다고 해요. AMD는 다가오는 차세대 플래그십 CPU의 주요 블록에서도, 모델이 쓴 설계로 한 자릿수 퍼센트 PPA 이득을 확인했다고 해요. 앞으로는 GPU와 CPU 모두에서 가장 최적화된 기준 대비 추가 PPA 개선을 기대한다고 해요.

### 오픈소스 RISC-V 코어 평가

생산 설계에서 모델이 개선을 낼 수 있음을 본 뒤, 세대별 칩 설계 능력을 재려고 오픈소스 32비트 RISC-V 코어 두 개로 각 모델을 시험했어요. PicoRV32는 FPGA용 소형 코어이고, OpenTitan은 보안 칩의 임베디드 프로세서로 Ibex를 써요. 둘 다 임베디드·마이크로컨트롤러급의 완전한 프로세서 코어예요.

각 모델에 원래 하드웨어 기술을 주고 처리량(초당 명령 수)을 높이도록 했어요. 시뮬레이션으로 출력을 검사하고, 검사에 실패하거나 원래 코어 면적의 16배를 넘기면 점수는 0이에요. 통과한 설계는 모델에 숨긴 워크로드의 클록당 명령 수를 재고, 기하평균에 Yosys로 추정한 최대 클록 주파수를 곱해 초당 명령 수 추정치를 냈어요. 같은 제약에서 본 최고 처리량을 1.0으로 두고, 차트는 0점 실행을 포함한 평균 점수를 보여요.

실행당 약 112,000토큰의 비슷한 예산에서 GPT-6.2 Astra가 두 코어 모두 평균 점수가 가장 높았고, GPT-6.1 Sol도 두 코어에서 GPT-5.6 Sol을 앞섰다고 해요. PicoRV32에서는 약 112,000토큰에서 GPT-6.2 Astra 점수가 GPT-6 Astra의 약 두 배예요. Ibex에서는 GPT-6.2 Astra의 평균 점수가 더 큰 예산에서도 계속 오르고, GPT-6 Astra와 GPT-6.1 Sol은 더 가깝다고 해요.

두 번째 과제는 서면 요구사항과, 코어가 시스템 나머지와 연결되는 방식을 보여 주는 오픈소스 코드 템플릿을 주고, 데이터 이동과 단계 분할을 모델이 고르게 했어요. 정확성 검사, 메모리·캐시 설정, 처리량 목표는 RTL 최적화 과제와 같았어요. 약 112,000토큰에서 다섯 모델 모두 기존 설계를 고칠 때보다 서면 요구사항에서 설계할 때 점수가 더 높았고, PicoRV32와 Ibex 모두 그랬어요. GPT-6.2 Astra는 Ibex에서 이득이 더 컸어요. 전체 평가는 두 과제, 두 코어, 모든 토큰 예산을 합쳐 채점된 실행 9,881건이에요. PicoRV32 명세에서 GPT-6.2 Astra는 약 112,000토큰 근처에서 평균 점수 0.7을 넘고 다음 두 예산에서도 더 높아요. Ibex에서는 같은 부근에서 약 0.75예요.

서면 요구사항에서 시작하면 원래 코어에 있던 성능 카운터나 추가 명령 같은 기능을 빼 둘 여지가 있고, 그 기능이 시험 워크로드 처리량에는 거의 도움이 되지 않아 점수 우위의 일부가 설명될 수 있다고 글이 밝혀요. 그런 기능을 요구하고, 회로 면적 한도를 더 엄격히 하며, 물리 합성 후 타이밍을 검사하면 생산 칩 설계에 더 가까운 시험이 될 것이라고 해요.

다음 단계로, RISC-V 평가에서 새 프로세서 아키텍처를 탐색하고 Jalapeño와 AMD 차세대 플래그십 GPU·CPU 같은 생산 설계에 순증 개선을 보탠 만큼, 시놉시스와 협력해 전문 칩 설계자처럼 시놉시스 EDA 도구를 쓰는 새 모델 GPT-Synopsys를 훈련한다고 해요.
