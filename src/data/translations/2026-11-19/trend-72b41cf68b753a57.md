사이드핸드는 클로드, 코덱스, 커서나 다른 MCP 클라이언트가, 지금 쓰는 창 뒤에 있는 윈도우 앱을 읽고 조작하게 해요. 마우스를 움직이거나 키보드를 빼앗지 않고, 입력하고 클릭하고 목록에서 고르고 화면을 텍스트로 읽어요. 슬로건은 “에이전트가 윈도우 앱에서 일하고, 키보드는 당신이 유지한다”예요.

벤치마크 과제에서는 메모가 키보드를 끝까지 쥐고 있었고, 잃은 시간은 0초, 창이 앞으로 나오지 않았고 커서로 움직이지 않았다고 해요. 가려진 창에서도 동작해 앞 창을 계속 쓸 수 있다고 해요. 컨트롤당 짧은 한 줄이라 그 과제는 277토큰이 들었고, 다른 도구는 2,448부터 13,425토큰이었어요. 창을 읽는 토큰은 전형적인 앱에서 agent-desktop보다 약 4–5배, 에지 페이지에서는 약 20배 적다고 해요. 과제를 2.0초에 끝냈고, 끝낸 다른 도구 윈도우-MCP와 터미네이터는 65.5초와 68.0초가 걸렸다고 해요. 사이드핸들과 agent-desktop은 docs/benchmark.md에서 측정했고, 컴퓨터 사용 칸은 벤더 페이지를 인용하며 더 많은 비교는 docs/comparison.md에 있다고 해요. 비교표에서는 클로드·챗GPT의 컴퓨터 사용이 윈도우에서 다른 창을 가리거나 포인터를 움직이고 전면을 차지한다고 적혀 있어요.

빠른 시작은 윈도우 10 또는 11과 Node 18.3+가 필요하고, MCP 클라이언트에 npx -y sidehand mcp 서버를 넣는 방식이에요. 클로드 코드, 커서(~/.cursor/mcp.json), 코덱스, 클로드 데스크톱, pi 설치 명령이 나와 있어요. 네이티브 윈도우에서 클로드 데스크톱, 커서, 코덱스는 cmd /c npx가 필요하고, 코덱스 TOML, CLI, 클로드 코드 가드 훅, SIDEHAND_ALLOW는 docs/setup.md에 있다고 해요. sidehand doctor로 설정을 점검하라고 해요.

사용 예는 tree로 창의 컨트롤을 참조(e4 등)와 함께 텍스트로 보고, act로 type·click·select 등을 실행하는 식이에요. ocr은 게임, Qt, 캔버스처럼 직접 그린 창을 윈도우 OCR로 읽고, wait는 특정 글자의 컨트롤이 나타나거나 사라질 때까지 기다리며, window·launch는 포커스를 빼앗지 않고 창을 옮기거나 앱을 켠다고 해요. capture와 mask는 가려진 창 스크린샷과 영역 가리기이고, 이메일·API 키·얼굴을 블러하거나 픽셀화한 뒤 붙여 넣을 수 있다고 해요. MCP와 pi는 같은 작업을 도구로 노출해요.

백그라운드에서 되는 일은 표로 정리돼 있어요. 윈32·윈폼, WPF, 크롬·에지, VS 코드에서 입력·클릭 등이 대체로 되고, 일부 동작은 UI 자동화나 동의(--allow-foreground, 전면을 가져도 된다는 허가)가 필요하다고 해요. 원본 마우스 입력을 읽는 게임은 보낸 클릭을 무시하지만 capture와 ocr은 동작하고, 관리자 권한 앱은 에이전트도 관리자로 실행해야 한다고 해요.

문제 해결은 doctor가 노드, WSL, 파워셸, 실행 정책, 엔진, OCR 언어를 확인하고 창은 건드리지 않는다고 해요. 네이티브 윈도우의 spawn npx ENOENT는 cmd /c npx, 코덱스 시작 시간 초과는 startup_timeout_sec = 60, 스크립트 실행 비활성화는 그룹 정책이라 관리자만 바꿀 수 있고, OCR 언어 팩이 없으면 추가하라고 해요.

보안으로는, 다른 창에서 읽은 텍스트가 에이전트로 가니 웹 콘텐츠처럼 취급해야 하고, 페이지나 메시지가 에이전트에게 지시를 시도할 수 있다고 해요. SIDEHAND_ALLOW로 볼 수 있는 창을 제한하고, 파워셸로 넘기는 문자열은 인용하거나 거절한다고 해요. 라이선스는 PolyForm Shield 1.0.0이고, 직장 사용을 포함해 어떤 용도로든 무료이지만 사이드핸들이나 블루-비가 이를 써서 제공하는 제품과 경쟁하는 제품을 만들거나 제공하는 것은 예외이며, 사이드핸들이 특허를 침해한다고 주장하는 사람에게는 특허 라이선스가 끝난다고 해요. 상업 라이선스는 이슈를 열라고 해요.
