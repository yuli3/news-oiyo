OpenAI Codex 저장소에 올라온 이슈로, 제목은 "CLI: `daemon_auto_start`를 opt-in으로 — 상주하며 스스로 업데이트하는 백그라운드 데몬은 기본값이 되면 안 된다"예요. 작성자는 Linux(WSL2)에서 `npm install -g @openai/codex`로 설치한 **CLI 0.157.0**을 쓰고 있어요.

### 무엇이 일어나나
0.157.0부터 대화형 `codex` 세션을 열기만 해도 다음 일이 벌어진다고 해요.

1. **상주 백그라운드 데몬 시작** — `codex app-server --managed-daemon`이 TTY 없는 별도 세션에서 돌고, Codex 창을 모두 닫아도 PID 1로 재부모화(reparent)돼 `codex app-server daemon stop`이나 재부팅 전까지 계속 살아 있어요.
2. **플랫폼 패키지 통째 복사** — 약 374MB(`codex`, `codex-code-mode-host`, 번들된 `bwrap`/`zsh`/`rg`)를 `~/.codex/packages/app-server-daemon/releases/<version>/`에 복사하는데, npm이 방금 설치한 것과 바이트 단위로 같아요. 데몬은 이 복사본에서 돌기 때문에 이후 백엔드 버전이 패키지 매니저로 설치한 CLI 버전과 분리돼요.
3. **분리된 업데이터 실행** — `codex app-server daemon pid-update-loop`가 시작 5분 뒤, 이후 매시간 업데이트를 확인하고 새 릴리스를 내려받아 백엔드를 재시작해요. 진행 중인 턴이 죽을 수 있어요(#40969).
4. **처음 띄운 세션의 환경 고정** — 작성자는 호출마다 `HTTPS_PROXY`를 바꾸는 래퍼로 Codex를 띄우는데, 데몬은 첫 세션의 프록시 변수를 계속 들고 있어서 이후 세션이 어떻게 실행되든 그 프록시로 나가요. 데몬의 cwd·터미널이 세션과 다르다는 #42457, #37537도 같은 원인으로 보여요.

### 요청 사항
CLI에서 가장 덜 놀라운 기본값은 "백엔드가 창과 함께 살고 죽으며, 내가 설치한 바이너리를 돌리고, 백그라운드에서 혼자 업데이트하지 않는 것"이라는 주장이에요. 공유·자기 갱신 데몬은 Remote Control이나 데스크톱 앱에는 맞으니 거기서 켜거나, 사용자가 `codex app-server daemon start`/`bootstrap`을 명시적으로 실행할 때만 켜자는 제안이에요. 기본값을 유지한다면 최소한 ① 마지막 클라이언트가 끊기면 자동 시작된 데몬을 종료하고 ② npm·brew·pacman 같은 패키지 매니저 설치본이면 복사·자기 갱신 없이 설치된 바이너리를 돌려 달라고 했어요.

### 끄다가 발견한 버그와 우회법
`codex app-server daemon stop`은 app-server만 멈추고 `pid-update-loop` 업데이터는 남겨 둬요(70초 뒤에도 살아 있어 직접 kill해야 했다고 해요). 작성자의 우회법은 이래요.

```sh
codex features disable daemon_auto_start
codex app-server daemon stop
pkill -f 'app-server daemon pid-update-loop'
rm -rf ~/.codex/packages/app-server-daemon
```

플래그를 끄면 새 TUI 세션이 더는 데몬을 띄우지 않아요.

### 댓글 반응
"작은 버전 업에서 예고 없이 정체 모를 서버·프로세스를 만들면 안 된다"는 공감, "고쳐지기 전까지 CLI를 못 쓰겠다"는 의견이 이어졌어요. Windows 10 LTSC에서도 재현되며 `config.toml`에 `daemon_auto_start = false`를 넣으면 해결된다는 확인도 있었어요.
