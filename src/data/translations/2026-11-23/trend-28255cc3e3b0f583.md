Ars Technica 기사 본문 전체를 읽고 옮겼어요(독자 댓글은 제외했어요).

### 실험 방법

많은 AI 앱은 OpenRouter나 Vercel 같은 'AI 라우터(게이트웨이)'를 거쳐요. 라우터는 프롬프트를 받아 가격이나 적합도를 기준으로 추론 엔진에 보내요. 보안 회사 Dragos의 최고연구책임자 HD Moore는 빈 AWS 계정에 묶인 실제 액세스 키, SSH 비밀번호, 고유 URL·DNS 이름, 비공개 git 저장소 주소를 만들고, 각 비밀값을 단 하나의 프롬프트에 넣어 한 제공업체에만 보냈어요. 누군가 그 값을 쓰면 어느 고리에서 샜는지 알 수 있는 '카나리'예요.

### 발견한 것

- 최소 3곳의 AI 제공업체가 공격자에게 침해돼 프롬프트가 빼돌려졌어요. 한 곳에서는 10월 말 특정 시간대에 보낸 요청이 전부 도난당했고, 모델이 돌기도 전에 거절된 요청까지 새어 나가 공격자가 '정문'에서 요청을 복사하고 있었다고 봤어요. 다른 두 곳에서는 ZDR 표시가 붙은 요청도 도난당했어요.
- 공격자는 몇 시간 만에 키를 시험하고, S3 버킷·Secrets Manager·Parameter Store를 뒤지고, AWS Bedrock 모델을 켜고 자기 IAM 사용자를 추가했어요. 미끼 키는 AWS API 호출에 "수만 번" 쓰였어요. 두 업체에 보낸 비밀값은 같은 임대 서버에서 거의 동시에 쓰여 같은 공격자로 보여요.
- 일부 리셀러는 낮은 가격으로 요청을 끌어들인 뒤 요청 로그를 켜 두고 기다렸어요. 같은 모델을 다른 판매자로 보냈을 때 한쪽 경로의 값만 재사용돼 리셀러 책임임을 확인했어요.
- 한 중국 AI 연구소의 시스템은 7~10월 자사 모델로 보낸 프롬프트 절반 이상, '데이터 수집 안 함'·ZDR 요청의 약 3분의 2에서 비밀 URL을 2~3일 뒤 가져갔어요. 이 연구소 모델을 재판매하는 미국 업체를 거친 요청도 같은 스크래퍼가 따라왔어요. 미국의 한 업체는 검색 엔드포인트로 한 번 쓴 URL을 두 달 넘게 지나서도 크롤링했어요.

### 업데이트와 권고

기사는 11월 21일 업데이트에서 OpenRouter가 고객에게 일부 프롬프트가 읽혔을 수 있다고 메일을 보냈다고 전해요. 노출은 중국 모델 업체 MiniMax로 간 프롬프트와 관련됐고, 직접 보냈든 AtlasCloud·Novita·StreamLake를 거쳤든 미끼 URL이 접근됐다고 해요. OpenRouter는 MiniMax 엔드포인트에서 ZDR 표시를 뗐어요.

Moore는 가장 확실한 예방은 온프레미스 자체 호스팅이고, 그게 어렵다면 계약 하나·개인정보 정책 하나만 읽으면 되는 1차 제공업체와 직접 거래하라고 권해요. 라우터를 쓴다면 기본 제공업체 풀을 받아들이지 말고 상위 제공업체를 직접 고르라고 했어요. 기사는 이 연구가 AI 생태계 전반의 느슨한 보안을 보여 준다고 평가했어요.
