Roman Komarov(kizu)의 블로그 글을 끝까지 읽고 옮겼어요.

### 결정 내용

3주 전 CSS Working Group 회의에서 "[css-forms-1] Cursors for base appearance" 이슈를 논의하고 마지막 댓글의 커서 규칙을 채택하기로 결의했어요. 요약은 이래요.

> 포인터는 "이걸 클릭하세요", 텍스트 커서는 "글자를 입력할 준비", 잡는 손은 "끌어 옮기세요".

채택된 규칙 중 하나는 `select`, `option`, 체크박스·라디오, `button`과 버튼형 `input`들, `::file-selector-button`에 `cursor: pointer`를 주는 거예요. 버튼만 남기면 이렇게 돼요.

```css
button {
  cursor: pointer;
}
```

다만 이건 브라우저 기본 스타일을 바꾸는 게 아니라 `appearance: base-…`를 쓰는 요소에만 적용되는 규칙이에요. `!important`가 없어 얼마든지 덮어쓸 수 있으니, 싫은 사람은 스타일시트에서 `default` 등으로 바꾸면 돼요.

### 필자의 입장

필자는 늘 이 결정을 지지해 왔어요. 2013년 "Correct Cursor on Active Elements" 글을 썼고, 2017년 첫 CSSWG 이슈로 "모든 인터랙티브 요소를 포인터 커서로 표시하자"를 열어 명세의 비규범 부분이 바뀌었어요. 그 뒤로 새 논거는 보지 못했다고 해요.

### "OS는 그렇게 안 한다"는 반론에 대해

- 가장 흔한 반론은 "OS가 그렇게 하지 않는다"인데, 필자는 OS가 마지막으로 UI를 혁신한 게 언제냐고 되물어요.
- "다음엔 OS 커서도 바꾸자는 거냐"는 반문에는 "네, 그러면 좋겠다"고 답해요.
- 데스크톱의 비네이티브 앱 절반 정도가 이미 인터랙티브 요소에 `cursor: pointer`를 써요. Cinny, Discord, Signal, Slack, Steam, VS Code를 예로 들어요.
- 기본 커서는 특정 픽셀을 가리키는 일 하나만 잘하고, 아무것도 전달하지 않는다고 해요.

### 커서가 더 필요하다

반대 측 논거 중 필자가 전적으로 동의하는 건 **버튼과 링크가 서로 다른 커서를 가지면 좋겠다**는 것, 그리고 새 탭으로 열리는 링크도 일반 링크와 달라야 한다는 거예요. 그래도 페이지의 빈 공간, 버튼, 링크 세 가지에 커서 두 종류만 줄 수 있다면, 버튼이 링크보다 빈 공간과 더 닮았다고 보는 생각은 이해할 수 없다고 마무리해요.
