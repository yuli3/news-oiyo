AI타임스 기사(임대준 기자) 본문 전체를 읽고, 기사 내용을 우리말로 다시 정리했어요(원문이 한국어라 번역이 아니라 요약·정리예요).

### 무엇을 공개했나

딥시크 하네스 개발팀이 10월 31일(현지시간) 공식 위챗에 **'슈퍼 에이전트 설계 탐구: 더 자율적인 에이전트 시스템을 향해'**라는 기술 문서를 올리고, 이 구조를 구현한 **dsh-superagent** 소스 코드를 GitHub에 공개했어요. 기사는 앤트로픽 클로드 코드와 오픈AI 코덱스를 추격하려는 움직임으로 봐요.

### 6개월의 흐름

- 5월: 클로드 코드를 경쟁 대상으로 하네스 전담팀 구성(제인스트리트 출신 추이톈이가 이끎)
- 6월: 개발 인력 채용 확대
- 8월: 오픈소스 개발 환경 '딥시크 하네스' 공개
- 10월 말: 팀 단위 업무 자동화를 겨냥한 슈퍼 에이전트

### 구조

모델 코딩 능력이 좋아져도 개발자가 에이전트마다 지시하고 확인해야 하면 생산성에 한계가 있다고 보고, **작업을 나누는 '라우터'와 실제 일을 하는 '워커'를 분리**했어요. 라우터는 팀 대화와 GitHub 이벤트를 보고 작업을 배분하고, 워커들은 독립 환경에서 코드 수정과 오류 해결을 병렬로 해요. 대화방에서 버그가 언급되면 미리 허용된 규칙에 따라 분석·수정하고 PR을 올려 검토를 요청하는 식이에요. 딥시크는 내부에서 실제 오류 수정과 코드 리뷰 대응에도 쓰고 있대요.

### 실험 결과와 한계

메시지 약 300개, 작업 요청 20개 모의 상황에서 **작업 95%를 15.7분 안에** 처리해, 단일 세션 방식(29.5분)보다 **약 47% 단축**됐어요. 다만 캐시 토큰은 더 많이 썼어요. 기사는 이 실험이 코딩 성능이 아니라 **다중 작업 처리 효율**을 잰 것이고 클로드 코드·코덱스와 직접 비교한 것도 아니라고 짚어요. 두 경쟁 제품도 이미 하위 에이전트, 병렬 실행, 백그라운드 자동화를 지원해요. 딥시크도 공개 코드는 **연구용 프로토타입**이고 내부 시스템과 차이가 있으며 일부 자동화는 구현되지 않았다고 밝혔어요.

### 의미

코드를 **MIT 라이선스**로 공개하고 여러 AI 모델을 연결할 수 있게 설계해 외부 개발자 참여를 유도하는 점에서, 딥시크가 모델 공급을 넘어 코딩 에이전트 플랫폼으로 넓히려는 전략으로 해석돼요. 기사는 실제 현장의 성능·안정성·운영 비용 검증은 아직 초기 단계라고 정리해요.
