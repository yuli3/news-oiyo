Atuin 블로그 글을 끝까지 읽고 옮겼어요.

### 왜 만들었나

글쓴이는 지난 1–2년 사이 자기 기기에서 돌아가는 명령의 절반 이상을 자신이 아니라 코딩 에이전트가 쓴다고 말해요. 셸 기록은 Atuin 덕분에 어디서나 따라오지만, 에이전트 세션은 노트북, 개발 서버, exe.dev 임시 인스턴스, 독일의 저렴한 베어메탈 서버 등에 흩어져 찾기 어렵고 곧 잊혀요. 셸 기록은 "무엇을 했는지"만 남기지만 에이전트 세션에는 명령, 출력, 의도, 시도한 과정이 평문으로 모두 남아 있는데도 활용하지 못한다는 문제의식이에요.

### Threads가 하는 일

- Atuin **18.24**부터 여러 기기의 에이전트 세션을 검색하고, 어디서든 이어 가거나 다른 에이전트 하네스로 **포크**해요. 예: 개발 서버의 Claude Code에서 시작해 노트북의 Codex에서 마무리.
- Atuin의 동기화 엔진은 append-only 로그면 무엇이든 동기화할 수 있고, 대부분의 AI 세션이 바로 그런 형태예요.
- 셸 기록처럼 **종단간 암호화**로 동기화돼 회사도 내용을 못 읽어요. 호스팅 서버, 자체 서버, 로컬 전용 중 고를 수 있고, 세션 수집은 옵트인이에요.
- 지원: Claude Code, Codex, Pi, Omp, OpenCode(추가 예정).
- `atuin mcp`로 에이전트가 이전 세션을 직접 검색·참조해요. `atuin mcp install claude/codex/pi/opencode`로 설치해요.

### 사용 예

- **배포되지 않은 작업**: 온보딩을 여러 번 고쳤다 버렸는데, 이제 에이전트가 이전 시도와 포기 이유를 찾아 긴 명세 없이도 의도를 파악해요.
- **오브젝트 스토어 장애**: 보안 사고 여파로 키를 교체했더니 아바타 업로드 권한이 빠졌어요. 매일 도는 Sentry 분류 에이전트가 원인을 그날 실행한 명령까지 추적했고, 다른 에이전트가 그 조사를 찾아 더 빨리 고쳤어요.
- **기기 간 포크**: 느린 기기의 IO 조사를 SSD가 빠른 MacBook으로 포크해 이어 갔고, 원래 기기의 스레드가 그 결과를 가져와 수정까지 만들었어요.

### 팀

Git, 이슈 트래커, 문서에 남지 않는 맥락이 개인 세션에 흩어져 있어요. 그래서 에이전트 스레드를 Git 브랜치처럼 넘겨주는 옵트인 팀 공유를 만들고 있다고 해요. 설치는 공식 설치 스크립트로 하고 `atuin resume`으로 시작해요.
