AI타임스 기사를 읽고 핵심을 다시 정리했어요. 기사 문장을 옮기지 않고 요점만 재구성했어요.

### 제브는 어떤 모델인가
제브는 긴 글을 생성하는 대신 정해진 형식으로 **선택지나 점수 같은 구조화된 답**을 돌려주는 모델이에요. 조건 판단이나 업무 절차 자동화에 쓰여요. 1.14 버전은 10월 14일(현지시간) 공개됐어요.

### 새로 생긴 것
| 기능 | 내용 | 켜는 법 |
|---|---|---|
| 이미지 입력 | PNG·JPEG를 `assets`에 등록해 `state`·`instructions`·`criteria`에서 참조, 파일당 16MB·요청당 32MB, 가로세로 256~1568px | `TypeSafe-Danger-Zone-Images: true` |
| 박스 질문 | 이미지 속 객체 위치를 0~1 비율 경계와 신뢰도로 반환 | 실험 기능 |
| 장문 컨텍스트 | 기본 요청당 6만4000·질문당 3만2000토큰 → 둘 다 26만2000토큰 | `TypeSafe-Danger-Zone-Long-Context: true` |
| 피드백 옵트인 | 쿼리를 학습엔 쓰지 않고 버그 찾기·디버깅에만 활용 | 옵트인 |

회사는 검증이 덜 된 기능도 개발자가 골라 써 볼 수 있게 API에 **'위험 구역' 플래그**를 도입했고, 이 기능들은 운영 환경에 바로 쓰기를 권하지 않는다고 분명히 했어요.

### 주의할 점
- 이미지 분석은 텍스트보다 정확도가 떨어질 수 있어 질문을 작게 쪼개라고 권해요.
- 자체 시험(일부가 잘린 그림 36개)에서 경계마다 따로 묻는 질문 4개는 잘린 사례 30개, 한 번에 묻는 방식은 26개, 박스 윤곽 방식은 20개를 찾았어요.
- 박스 기능은 객체가 없어도 좌표를 돌려주므로 존재 여부를 묻는 질문을 함께 쓰라고 해요.
- 긴 입력일수록 신뢰도가 떨어질 수 있어 꼭 필요할 때만 장문을 쓰라고 해요.

### 성능·제공·가격
전반적 성능은 소폭 개선됐고 다국어 처리 향상을 가장 크게 기대한다고 해요. 자체 평가에 유리한 편향이 있을 수 있다고 인정하며 실제 사용 사례로 검증해 보라고 권했어요. 지금은 `jev-preview` 별칭으로 쓸 수 있고 약 일주일 뒤 `jev-latest`가 1.14로 바뀌어요. 1.13은 당분간 유지하고, 종료 시 1.13은 60일 전, 1.14는 30일 전에 알린다고 해요. 가격은 입력 토큰 100만 개당 0.042달러(10억 개당 42달러)이고 출력 토큰은 무료, 이미지도 입력 토큰 기준으로 과금돼요.
