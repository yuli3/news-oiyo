Hacker News가 요청을 막아(419) 원 글을 읽지 못했어요. GeekNews가 HN 답변을 주제별로 정리한 글을 기준으로 썼어요.

### 질문
작성자는 한 Meta 엔지니어의 LinkedIn 글에 공감하며 물었어요. AI로 배포 속도가 너무 빨라져 코드를 한 줄씩 검토하기엔 시간이 너무 걸리고, 큰 구조는 알아도 세부 동작은 모른 채 개발을 끝낼 수 있다는 고민이에요. 만드는 것을 이해해야 한다는 엔지니어의 본능과, 이것이 새 표준이 될 수 있다는 현실 사이에서 **어디까지 이해해야 안심할 수 있는지**를 물었어요.

### 답변 정리
- **설계는 사람이**: 구성 요소의 역할, 상호작용, 추상화 계층을 먼저 정하면 개별 함수를 다 기억하지 못해도 시스템을 이해할 수 있다는 의견(bitwizeshift)이 있었어요. tptacek은 ChatGPT와 긴 대화로 설계를 다듬고 Markdown 계획을 직접 고쳐 구현 에이전트에 넘긴다고 했어요. 핵심은 설계에 관여하고 이해하고 승인하는 것이라는 거예요.
- **반론**: 구현해 봐야 설계 문제가 드러나니 둘을 오가야 한다는 의견(stingraycharles)도 있었어요.
- **모호함 줄이기**: 구현 전에 에이전트가 인터뷰하듯 질문하게 해 명세를 구체화한다는 의견(iamwil), 차별점이 되는 결정만 직접 하고 나머지는 위임한다는 의견이 나왔어요.
- **문서를 확인 지점으로**: 항공 시뮬레이션·CAD/CAM을 만드는 lp92는 기능 설계서와 구현 계획을 승인한 뒤에만 코드를 바꾸고, 수정 뒤 아키텍처 문서를 갱신하게 한다고 했어요. physicles는 AI 설명을 읽기만 하면 기억에 덜 남는다며 명세를 직접 쓴다고 했어요.
