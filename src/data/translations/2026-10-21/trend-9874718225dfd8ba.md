GitHub README 앞부분(소개와 상황별 안내)을 기준으로 옮겼어요. 링크 목록 본문은 옮기지 않았어요.

### 무엇인가
확장 가능하고(scalable), 안정적이며(reliable), 성능 좋은(performant) **대규모 시스템의 패턴**을 보여 주는 정리된 읽기 목록이에요. 개념은 저명한 엔지니어의 글과 믿을 만한 자료로 설명하고, 사례는 수백만에서 수십억 사용자를 다루는 실전 검증 시스템에서 가져와요.

### 상황별 안내
- **시스템이 느려질 때**: 먼저 문제를 구분하라고 해요. 한 사용자에겐 빠른데 부하가 크면 느린 건 **확장성 문제**, 한 사용자에게도 느린 건 **성능 문제**예요. 설계 원칙과 기술 기업들의 해결 사례를 보라고 해요. 빅데이터·딥러닝 규모로 일하는 사람을 위한 "intelligence" 섹션도 있어요.
- **시스템이 다운될 때**: 우버 전 CTO 투안 팜의 "모든 걸 잃어도 침착하면 다시 다 지을 수 있다"는 말을 인용하며, 침착하게 가용성과 안정성을 챙기라고 해요.
- **시스템 설계 면접**: 화이트보드에 그리기 전에 면접 노트와 다이어그램이 있는 실제 아키텍처를 보고, 빅테크 엔지니어들의 발표를 참고하라고 해요.
- **꿈의 팀을 만들 때**: 팀 확장의 목표는 인원이 아니라 **팀의 산출과 가치를 키우는 것**이라며, 채용, 관리, 조직, 문화 측면의 기업 사례를 모았어요.
