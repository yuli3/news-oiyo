GeekNews Ask GN 글과 달린 댓글 하나를 모두 읽고 옮겼어요. 원문 자체가 짧은 질문 글이에요.

### 질문 내용
작성자(noahl)는 DevOps로 일하는데, 여러 팀이 Claude나 Codex로 **팀 에이전트**를 만들어 배포하고 Slack에 연동하고 있다고 해요. 자동화 자체는 문제가 아니지만 운영팀 입장에서는 두 가지가 걸린다고 말해요.
- **중복**: 대부분 에이전트가 코딩과 Q&A용이라 기능이 많이 겹쳐요.
- **보안**: 어떤 에이전트가 어떤 API 키를 쓰는지, 어떤 스킬이 설치됐는지 인프라 수준에서 확인할 방법이 없어요.

업계에서 이를 **Agent Sprawl**이라고 부르는데, 다른 회사는 어떻게 다루는지 물어요.

### 달린 답변
댓글은 아직 하나예요. 비개발자 개인 사용자(dkkim1110)가 혼자 Claude Code 대화방을 열 개 넘게 쓰다 보니 비슷한 문제를 작게 겪었다고 해요. 두 방이 같은 일을 동시에 하거나, 이미 끝난 일을 다른 방이 다시 하려 했대요. 해결책은 단순했어요. 공지 파일 한 장에 방마다 "맡은 것, 안 맡은 것"을 적게 했더니 겹치는 방이 보였고, 겹치면 새로 만들지 않고 한쪽에 몰았다고 해요. API 키와 권한 관리는 자기가 답할 수준이 아니라며 다른 답을 기다린다고 했어요.
