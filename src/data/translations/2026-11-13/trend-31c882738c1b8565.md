Rust 공식 블로그 발표문을 읽고 옮겼어요. 수집 상한(6,000자)에서 잘려 '크기 0 타입 만들기' 이후 항목(Cargo 미사용 의존성 보고, 캐시 충돌 감소, min-publish-age, 안정화 API 목록)은 제목만 확인했어요.

### 업데이트

`rustup update stable`로 1.100.0을 받을 수 있어요.

### never 타입

**10년 동안 다섯 번 안정화에 실패한 끝에** never 타입이 안정화됐어요. 코드에서는 `!`로 쓰고, 값을 만들 수 없는 대표 타입이에요. `return`, `break`, `std::process::exit`처럼 제어 흐름을 끝내는 표현식의 타입이 `!`이고, 그 뒤 코드는 도달할 수 없어요. `!`는 어떤 타입으로든 바뀔 수 있어서 `match`의 한 갈래에서 `return`해도 타입 검사를 통과해요.

이전에도 함수 반환 타입(`-> !`)에는 쓸 수 있었지만 이제 어디서든 이름으로 쓸 수 있어요. 예를 들어 `Result<T, !>`를 받아 `let Ok(v) = res;`로 꺼내는 코드가 가능해져요.

`Infallible`도 never 타입의 별칭이 됐어요. 그래서 `Infallible`을 쓰던 옛 API가 `!`와 호환돼요. 이를 위해 **호환성을 깨는 변경**이 하나 들어갔어요. 2015·2018·2021 에디션의 'never 타입 폴백'이 `()`에서 `!`로 바뀌어요(2024 에디션은 이미 그랬어요). 대부분 눈에 띄지 않지만 제네릭 반환값을 무시하는 경우 같은 드문 상황에 영향을 줄 수 있고, 컴파일러가 도달 불가 코드를 더 많이 찾아낼 수 있어요. 오래전부터 경고를 내고 영향받은 공개 크레이트에 수정을 배포했으니, 의존성이 깨지면 업데이트해 보라고 해요.

### Allocator API

`allocator_api`의 핵심이 안정화돼, 라이브러리 작성자가 직접 만든 할당자를 표준 라이브러리 타입(현재는 `Vec`, `Box`)과 함께 쓸 수 있어요. 새로 안정화된 `Allocator` 트레이트가 그 기반이고, 'Allocators 1.0' 목표의 출발점이에요. 더 많은 컬렉션·포인터 타입 지원은 곧 이어질 예정이에요.

### DropGuard

`core::mem::DropGuard`는 값과 클로저를 받아, 가드가 버려질 때 클로저를 실행해요. `return`, `?`, 패닉 어느 경로로 빠져나가도 실행돼요. `Deref`·`DerefMut`를 구현해 값을 평소처럼 쓸 수 있고, `dismiss`로 클로저를 실행하지 않고 값을 돌려받을 수 있어요. 발표문은 문자열 여러 개를 파싱하다 하나라도 실패하면 `Vec`를 원래 길이로 되돌리는 '전부 아니면 전무' 예제를 보여 줘요.
