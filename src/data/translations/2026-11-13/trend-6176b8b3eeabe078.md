LinkedIn·Meta에서 대규모 AI 시스템을 만들었던 Alireza와 Majid가 Leeroo에서 엔터프라이즈 데이터용 AI 시스템을 만들고 있어요. 이번에 **Kapso**를 오픈소스로 공개했는데, 실험을 돌리고, 가장 좋은 해법을 배포하고, 매 실행에서 배우는 엔진이에요.

### 문제의식

데이터 작업은 조사 → 가설 → 실험 → 개선을 반복하는 일이고, 크고 지저분한 엔터프라이즈 환경에서는 이런 바텀업 방식만이 빨리 성과를 낸다고 봐요. 회의로 맥락을 모으거나 비즈니스 온톨로지를 먼저 정의하는 방식은 몇 분기, 길게는 몇 년이 걸린다고 해요.

예로 든 프로젝트는 30개 이상 소스 시스템 계열, 수천 개 테이블·변환, 수백 개 BI 리포트가 있는 기존 데이터 환경을 레이크하우스로 옮기는 일이었어요. 누구도 전체 연결 구조를 몰랐고, 저장소·dbt 모델·문서·데이터를 조사해 가설을 세우고 실험하며 배울 수밖에 없었다고 해요. 문서를 RAG로 넣는 것만으로는 특정 환경에서 실제로 시도해 보기 전까지 가치가 작다는 주장이에요.

### 작동 방식

- 목표와 성공 기준을 주면 배포 가능한 최적 해법을 향해 실험해요.
- 과거 실험에서 귀납·연역한 **교훈 은행**이 있고, 교훈마다 신뢰도(credence), 적용 조건, 근거가 붙어요.
- 아이디어 모듈이 교훈을 참고해 아이디어를 내고, 예산 대비 기대 수익으로 다시 순위를 매겨 상위안을 구현 모듈에 보내요.
- 실험이 접근할 수 없는 **검증 모듈**이 결과를 확인해 속임수를 막아요. 필요하면 실험 모듈이 지표·기준 변경을 제안하고 검증 모듈이 승인하거나 거절해요.
- 실행 후 `learn()`이 교훈의 점수와 적용 경계를 갱신하고, 은행 변경도 A/B 테스트할 수 있어요.
- 은행은 git 기반이라 `kapso experience share/list/update`로 공유·갱신해요.
- 모델·코딩 에이전트에 종속되지 않고, `kapso.deploy(solution, target_stack)`가 Docker, Modal, BentoCloud, LangGraph 같은 대상에 맞게 짧은 실험 루프를 한 번 더 돌려요.
