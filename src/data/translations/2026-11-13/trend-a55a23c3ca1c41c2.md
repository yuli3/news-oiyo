GitHub 저장소 README 전체를 읽고 옮겼어요. 수치는 모두 저장소가 기기에서 직접 쟀다고 밝힌 값이에요.

### 무엇인가

**smolmaxxing**의 목표는 "가지고 있는 가장 작은 하드웨어에서 돌릴 수 있는 가장 큰 언어 모델"이에요. TV 박스, 오래된 태블릿, 싱글보드 컴퓨터, 공유기에도 하루 대부분 노는 CPU·RAM·플래시가 있으니, 기기마다 실제로 돌릴 수 있는 가장 큰 모델을 찾고 커스텀 커널·메모리 절약·플래시 스트리밍으로 더 밀어붙인대요.

### 지금까지 두 기기

- **Xiaomi TV Box S(3세대)**: Amlogic S7D(Cortex-A55 4코어), RAM 1.9GB(쓸 수 있는 건 약 1GB), Android 14(루팅 없음). 일상용은 Qwen3.5-2B 7.7 tok/s, 가장 큰 모델은 Ling-mini-2.0 16B 5.1 tok/s.
- **iPad Air(2013)**: Apple A7(2코어), RAM 1GB(약 700MB), iOS 12.5.7(탈옥). 일상용은 Bonsai-1.7B(1비트) 24–26 tok/s, 가장 큰 모델은 Ling-mini-2.0 16B 2.6–4.5 tok/s.

두 기기 모두 모델 일부만 메모리에 두고 나머지는 필요할 때 플래시에서 읽어, 약 1GB RAM으로 8B·16B MoE 모델을 돌려요. 휴대폰, 싱글보드 컴퓨터, 공유기도 추가할 예정이에요.

### 작동 원리(llama.cpp 패치)

- **칩 맞춤 커널**: 1비트 룩업 테이블 커널, Cortex-A55용으로 다시 묶은 2비트·삼진(ternary) 형식, 내적 명령이 없는 A7용 버전.
- **모델당 RAM 줄이기**: 작은 모델 어휘 대부분은 거의 안 쓰여서 해당 출력 행을 버려요. TV에서는 모델 실행 중 런처와 Google 서비스를 멈추는 'headless' 모드도 써요.
- **플래시에서 전문가 페이징**: MoE는 토큰마다 일부 전문가만 쓰니 자주 쓰는 전문가만 RAM에 두고 나머지는 필요할 때 읽으며, 다음 레이어 전문가를 미리 읽어 둬요.
- **RAM보다 큰 dense 모델 스트리밍**: 플래시 최대 속도로 읽어요.

1비트 커널은 기본 NEON만 있으면 되고, 플래시 스트리밍은 RAM보다 모델이 큰 리눅스·안드로이드 기기 어디서나 된대요.
