### 왜 만들었나

모델이 강해지고 안전·보안 위험이 커질수록, 문제를 감지하고 필요하면 모델을 곧바로 멈추는 능력이 더 중요해진다고 OpenAI는 말해요. 그래서 **Control Room**을 만들었어요.

### Control Room이란

연구 인프라 전반의 모델 작업을 추적하고, 안전·보안 우려가 생기면 빠르게 멈추는 중앙 시스템이에요.

- 모델 학습·평가를 위한 에이전트 샘플링, 데이터 처리 등 **모든 연구용 추론 작업**을 연결해요.
- 불일치(misalignment) 모니터링 시스템과 함께 동작하고, 작업을 멈추거나 일시정지하기로 결정한 뒤 **35초 안에** 모델 출력을 멈춰요.
- 다른 시스템이 실패해도 계속 동작하고, **Control Room 자체가 다운되면 모델 출력을 멈추도록** 만들었어요.

필요가 가장 큰 연구 인프라에는 이미 배포됐어요. 외부 모델 서빙 스택은 원래 훨씬 중앙화돼 있고, 필요하면 배포를 빠르게 내리는 운영 능력이 이미 있다고 해요.

### 구성 요소

- **워크로드**: 강화학습 실험, 평가, 대량 샘플링, 데이터 처리처럼 실제로 돌아가는 작업이에요. 에이전트 추론을 하는 모든 연구 워크로드는 승인된 **안전 사례(safety case)**와 연결돼야 해요.
- **추론 엔진**: GPU에서 직접 도는 모델 자체, 모델의 두뇌예요. 한 워크로드가 여러 엔진의 모델을 쓸 수 있고, 한 엔진을 여러 워크로드가 쓸 수도 있어요.
- **Control Room 서비스**: 작업을 추적하고 모델 출력을 계속 만들어도 되는지 통제해요. 엔진은 요청을 처리하기 전에 서비스에 확인하고, 작업이 멈춘 상태면 서비스가 요청을 거부해 출력이 더 나오지 않아요.

### 통합 방식 (첫 단계)

새 작업을 시작할 때 워크로드 코드가 Control Room에 새 `job_id`를 요청해요. 이후 모델에서 토큰을 샘플링할 때마다 그 작업 정보와 함께 요청하는 구조예요.
