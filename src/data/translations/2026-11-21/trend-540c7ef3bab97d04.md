AI타임스 박찬 기자의 기사 본문 전체를 읽고 정리했어요.

### 퍼포먼스 팩토리

- 오픈AI는 19일(현지시간) 코덱스 기반 내부 성능 관리 시스템 **'퍼포먼스 팩토리(Performance Factory)'**의 개발 과정과 운영 방식을 공개했어요. 성능 저하 감지, 원인 분석, 수정안 제안, 배포 후 검증까지 자동화하는 시스템이에요.
- 도입 후 3개월여 동안 1,700건 이상의 성능 문제를 조사하고 600건 이상의 근본 원인을 찾았어요. 하루 평균 17건을 자동 조사한 셈이에요. 원인을 밝힌 사례 중 약 400건은 수정안 제안까지 갔지만, 배포된 수정안 중 코덱스가 쓴 코드를 그대로 적용한 건 15건에 그쳤어요.

### 어떻게 돌아가나

- 여러 에이전트가 역할을 나눠요. 성능 경고가 뜨면 첫 에이전트가 지표, 로그, 코드 변경 내역을 분석해 원인을 찾고, 다른 에이전트가 진단을 검증해요. 문제가 없으면 코덱스가 수정 코드를 써서 깃허브에 올리고, 엔지니어가 검토·배포한 뒤 시스템이 성능 회복을 확인해요.
- 예를 들어 한 에이전트가 챗GPT 대화 실패 원인을 이미지 다운로드 오류로 지목했는데, 검토 에이전트가 관련 내부 서비스가 이미 복구됐는데도 오류가 계속된다는 걸 발견하고 진단이 문제를 설명하지 못한다며 재조사를 시켰어요.

### 남은 과제

- 원인을 찾는 것보다 코드를 고치는 게 여전히 어려워요. AI가 불필요하게 복잡한 코드를 쓰거나 새 오류를 낼 수 있기 때문이에요.
- 지금은 코드 변경과 배포를 엔지니어가 최종 승인하고, 과거 성능 장애 사례로 수정안 정확도를 높이는 평가 체계를 만들고 있어요.
- 장기적으로는 위험이 낮은 수정을 사람 개입 없이 처리하고, 미리 설정한 경고가 없어도 잠재적 성능 저하를 스스로 찾는 기능을 추진해요.

오픈AI는 "코덱스가 챗GPT를 더 빠르게 개발하도록 돕고 있다면, 이제는 챗GPT를 빠르게 유지하는 데도 기여하고 있다"고 밝혔어요.
