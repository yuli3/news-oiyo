**PaperPilot**은 PDF와 문서를 다루는 툴킷으로, **순수 Rust**로 쓰였고 **로컬(또는 브라우저 메모리)**에서만 돌아가요. "PDF tools for your AI agent — and for you"를 내세워요.

### 같은 엔진, 여러 표면

| 표면 | 용도 |
|---|---|---|
| MCP 서버 | Codex, Claude Code, Kimi Code, Pi, Claude Desktop, Cursor 등에서 PDF 병합·분할·OCR·압축 |
| CLI | 배치·스크립트 워크플로 |
| 브라우저(WASM) | 설치 없이 탭 메모리에서 처리, 업로드 없음 |
| 데스크톱 | Tauri + Svelte GUI(뷰어, 마크업, diff) |
| 로컬 REST | `localhost:7823`에서 Python·Node·n8n 호출 |

Chromium, C++ 런타임, 클라우드 호출은 없다고 해요.

### 지금 할 수 있는 일 (v0.6)

- 정리: 병합, 분할, 회전, 페이지 삭제·재정렬·추출, booklet, N-up
- 최적화: 압축
- 추출: 일반 텍스트, OCR(순수 Rust PaddleOCR via rten)
- 보안: 워터마크, 서명 검증·제거, PII 스캔, deep sanitize
- 오피스 데이터: Excel → JSON/CSV

로드맵에는 PDF↔Markdown/HTML/JSON, PDF→Word/Excel/PowerPoint, 암호화·서명·편집 등이 이어져요.

### 에이전트에 연결

릴리스의 `paperpilot-mcp`를 받아 Claude Desktop 설정에 넣으면 "이 두 PDF를 합치고 압축해줘"처럼 쓸 수 있대요. `paperpilot-mcp --client-config codex`처럼 클라이언트별 설정 조각도 출력할 수 있어요.

### 왜 또 PDF 도구인가

1. 기본이 비공개(로컬/브라우저)
2. MCP가 1급 기능
3. CLI·MCP·REST·WASM·데스크톱이 **같은 Rust 코어**를 공유
4. lopdf, pdf_oxide, rten 등에 기반한 가벼운 의존성

소스에서 빌드하려면 Rust 1.75+, Node.js, pnpm이 필요하고, 벤치마크는 `cargo bench --workspace`로 재현할 수 있대요.
