vlt 블로그 글(다시 클라크, 2026-10-14) 전체를 읽고 옮겼어요.

### 무슨 일이 있었나
라이언 달은 지난주 **Deno 팀이 Cloudflare에 합류한다**고 발표했어요. Deno 런타임은 앞으로 1년에 걸쳐 정리되고, JSR 레지스트리는 Cloudflare 인프라에서 계속 운영돼요. 팀의 새 일은 Deno의 `celld`를 Cloudflare `workerd`에 합치는 거예요. 발표는 Deno 2 출시 정확히 2년 뒤였고, Bun은 10개월 전 Anthropic에 합류했어요.

### Deno가 남긴 것
필자는 "대안 런타임 실험은 끝났고 Node가 이겼다"는 결론은 틀렸다고 봐요. Deno는 프로덕션에서 임계점을 넘지 못했지만 **기존 강자에 압박을 줬다**는 거예요.

- 2018년 JSConf EU에서 라이언 달은 기본 거부 권한, TypeScript 일급 지원, 웹 표준 API, ESM 전용, 단일 실행 파일, 그리고 npm·package.json·node_modules 없음을 내걸었어요.
- URL 의존성은 곧 한계를 드러냈어요. `deps.ts` → `lock.json` → import maps로 4년간 하나씩 되돌렸고, 지금 Deno 문서도 HTTPS import보다 레지스트리를 권해요.
- 2022년 7월 Bun 0.1이 npm 호환을 들고 나오자 약 6주 뒤 Deno는 `npm:` 지정자를 발표했고, 2024년 10월 Deno 2에서 Node·npm 완전 호환을 마쳤어요.

### Node가 응답한 것
2018년 이후 Node는 전역 `fetch`, WebSocket, Web Streams, Web Crypto, 안정 테스트 러너와 `--watch`, `--env-file`, 단일 실행 파일 빌드, 안정 권한 모델, 기본 타입 스트리핑, `node:sqlite`, `require(esm)`을 들였어요. 필자는 Node 기여자들의 공을 인정하면서도, 다른 런타임이 먼저 내놓지 않았다면 이 속도는 아니었을 거라고 해요. "성숙한 프로젝트에 부족한 건 아이디어가 아니라 긴박감이고, 경쟁자가 그걸 준다"는 거예요. WinterCG(현 Ecma TC55) 표준 작업도 같은 압력에서 나왔어요.

### 패키지 매니저도 마찬가지
- Yarn(2016)이 결정적 설치와 lockfile을 가져왔고 npm 5가 이듬해 따라갔어요. pnpm은 중복 없는 node_modules를, Bun은 빠른 설치를 보여 줬어요.
- 설치 스크립트 기본 실행 중단은 pnpm·Bun·vlt가 먼저 했고, 공급망 웜이 잇따른 뒤 올해 6월 GitHub가 **npm 12도 기본 중단**한다고 발표했어요.
- JSR은 TypeScript 소스 배포, ESM 필수 등 다른 선택을 했고, 운영비가 싸고 API가 문서화돼 있어 살아남았다고 봐요.

### 앞으로
가장 인기 있는 독립 런타임 두 개가 이제 다른 본업을 가진 회사 안에 있어요. Bun은 Claude Code 팀과 "Chrome과 V8 같은 관계"가 될 거라 했고, workerd 로드맵은 Cloudflare 것이에요. 필자는 Deno 커뮤니티 포크가 나오는지가 생태계가 클라우드에 묶이지 않은 보안 우선 런타임에 돈을 낼 의지가 있는지 보여 줄 거라고 해요. 프로젝트가 늘 이기진 않았지만 아이디어는 대개 이겼다며, Deno 팀에 감사를 전하며 끝나요.
