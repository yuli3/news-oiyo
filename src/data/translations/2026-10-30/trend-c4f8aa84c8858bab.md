### "멈춘 에이전트는 실패한 에이전트보다 나빠요"

실패한 명령은 무엇이 잘못됐는지 말해 주지만, 멈춘 명령은 오후를 통째로 태운다는 게 이 플러그인의 문제의식이에요. 작성자가 하루 동안 겪은 실제 사례로 10분 넘게 멈춘 MCP 호출, 15분 넘게 늦게 보고된 루프 종료, 약 1시간 멈춘 서브에이전트를 들어요.

### 쓰기 전과 후

| 없을 때 | 있을 때 |
|---|---|
| Bash 명령이 알아챌 때까지 멈춰 있어요 | 제한 시간(기본 300초, 더 길면 `# eta:<초>`)에 종료돼요 |
| 루프가 끝나도 Claude가 조용히 넘어가요 | 다음 답변 첫 줄에 반드시 보고해요 |
| 백그라운드 작업을 잊어요 | 장부가 도구 호출마다 끝났거나 늦은 작업을 다시 알려요 |
| 서브에이전트가 한 시간 돌아요 | 10분 예산을 넘으면 보고하고 멈춰야 해요 |
| 두 세션이 휴대폰 하나를 두고 다퉈요 | 기기마다 소유자 하나, 비면 대기자를 깨워요(Flutter 팩) |

데몬도 네트워크도 없이 **훅과 스킬로만** 동작해요. 코어 플러그인 외에 프레임워크별 팩을 더할 수 있고, 첫 팩은 Flutter용이에요. 각 플러그인 README가 무엇을 실행하고 읽고 쓰고 종료하는지 정확히 적어 둔대요.

### 만든 이유

모두 Flutter 작업을 하던 평범한 하루에 생긴 일이라고 해요. 예를 들어 Marionette MCP 연결이 10분간 멈췄는데, MCP 호출은 Bash 시간 제한 밖에 있고 stdio MCP 서버의 기본 유휴 한도는 30분이라서 그랬다고 설명해요.
