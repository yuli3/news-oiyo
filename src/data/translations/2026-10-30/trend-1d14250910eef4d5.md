Flamerix AI의 GitHub Gist README 앞부분(문제와 측정, 해결 방식 개요)을 읽고 옮겼어요. 설치, 검증, 버전별 기록은 다 읽지 못했어요. 바이너리를 바꾸지 않는 비공식 우회 방법이고, 업데이트로 조용히 무효가 될 수 있다고 작성자가 밝혀요.

### 무슨 일이 일어나나요

작성자에 따르면 Claude Code는 약 30초마다, **백그라운드 에이전트 하나하나의 전체 대화 기록**을 그 에이전트의 모델(대개 Opus)에 보내 "가장 최근 행동을 3–5단어로 설명해 달라"고 요청해요. 그 답은 에이전트 패널의 상태 줄만 바꾸고, 모델이나 대화로는 들어가지 않아요. 끄는 설정은 없고, 2.1.232(2026년 8월)부터 기본으로 켜져 있다고 해요.

### 측정

DRIM이 Claude Code의 OpenTelemetry 내보내기에서 `claude_code.api_request` 이벤트를 `query_source`별로 묶어 보다가, `agent_summary`가 메인 대화보다 더 많은 비용을 쓰는 걸 발견했대요.

| query_source = agent_summary | 훅 적용 전 1주 | 적용 후 2일 |
|---|---|---|
| 전체 Claude Code 지출 비중 | 16.4%(메인 대화 15.7%) | 0% |
| 전체 API 요청 비중 | 19.7%(약 5건 중 1건) | 0% |
| 그 지출 중 Opus 비중 | 96% | — |
| 출력 토큰당 입력 토큰 | 약 9,000:1 | — |

여기서 지출은 청구서가 아니라 Claude Code의 요청별 추정치(cost_usd)예요. 구독제라면 잃는 건 사용 한도 여유라고 해요. 관련 이슈(#86879)에는 18–26%라는 독립 측정 4건이 모여 있다고 밝혀요.

### 해결 방식

`no-agent-summary.js`는 70줄 정도의 Bun preload예요. `BUN_OPTIONS=--preload`로 불러오고, 전역 `setTimeout` 중 요약 타이머만 감싸 멈춘다고 해요. Linux와 Claude Code 2.1.257–2.1.312에서 시험했고, macOS에서도 동작한다는 보고가 있대요. 작성자는 업데이트할 때마다 동작을 다시 확인하라고 권해요.
