### 도구 구성

글쓴이는 하드웨어와 소프트웨어를 20년 동안 해킹해 왔는데, 2026년엔 AI 덕분에 과정이 크게 빨라졌다고 해요.

- **DeepSeek Harness + DeepSeek v4.1 Flash**: 주력 AI예요. 가끔 Codex(Luna, Terra)도 쓰지만 DeepSeek이 성능 좋고 빠르고 싸다고 해요.
- **Ghidra + MCP 브리지**: 시장 최고의 무료 디스어셈블러·디컴파일러이고, MCP 브리지로 에이전트가 잘 다뤄요.
- **radare2, kuna**: CLI 도구예요. Ghidra만큼 좋진 않지만 훨씬 빠르고 AI가 쓰기에 더 나을 수 있어요.

### 작업 흐름

요즘은 분석할 바이너리에 에이전트를 붙이고 전용 스킬 묶음을 쓰면 나머지는 대체로 알아서 굴러간다고 해요. 기본 흐름은 이래요.

1. 바이너리 종류·플랫폼·빌드를 파악하고 맞는 디컴파일러를 골라요. 요즘 AI는 순수 x86·ARM 디스어셈블리만으로도 꽤 잘한대요.
2. 발견한 모든 것을 MD 파일로 기록하게 해요. 내 이해용 노트가 되고, 컴팩션이나 다른 에이전트로 넘길 때 흐름을 잃지 않게 하고, 에이전트가 빙빙 돌지 않게 해 줘요.
3. 주요 함수, 분기, import 함수 같은 기본 구조를 분석하게 해요. 데스크톱 실행 파일이든 웹사이트든 펌웨어 이미지든 마찬가지예요.

단순 디스어셈블리로 안 풀리면 브레이크포인트 디버깅, 원본에 로깅을 켜거나 프로브를 주입해 로그 남기기, 데스크톱 앱용 컴퓨터 사용이나 API로 제어하는 에뮬레이터 같은 외부 접근 주기, 구체적으로 다른 접근 지시하기(xref 대신 문자열 따라가기 등)를 써요. LLM의 대화와 사고 과정을 전부 읽어 막다른 길로 가는 걸 알아채고 방향을 잡아 주는 것도 중요하다고 해요.

### 자주 쓰는 스킬

- **Matt Pocock의 grill-me**: "더 진행하는 데 결정적인 질문을 최대 5개, 한 번에 하나씩 물어보라"는 프롬프트와 함께 써요.
- **Ghidra 등 RE 도구 스킬**: 내 도구 사용법을 설명한 스킬이 없으면 에이전트가 너무 빨리 포기한대요. ioma8/ghidra-decompile-skill(Java 스킬 + Ghidra 스크립트 22개)을 공개했어요.
- **가설 디버깅**: 막힌 에이전트에게 가설을 세우고, 디스크의 CSV 표에 적고, 확실히 증명·반증할 실험을 설계하고, 결과를 기록하는 루프를 강제해요. 과학적 방법의 변형으로, 무한 추측을 막는 데 결정적이라며 ioma8/hypothesis-debugging으로 공개했어요.

구현은 프로토타입·프로브용으로 uv를 쓴 Python, 실제 해킹 구현은 Rust예요. Rust 컴파일러가 엄격해 에이전트에게 강력한 피드백 루프를 준다는 이유예요.
