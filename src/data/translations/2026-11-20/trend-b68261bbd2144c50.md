### 무엇을 공개했나

허깅페이스가 '큐원3.8-27B'용 LoRA 어댑터 '큐원3.8-27B-pi-adapted'를 내놨어요. 오픈소스 코딩 에이전트 도구 '파이(pi)'에 최적화한 거예요. LoRA는 기존 모델의 구조와 가중치는 그대로 두고 작은 추가 가중치만 학습해, 특정 에이전트의 도구와 작업 방식에 맞춰 성능을 끌어올리는 기술이에요.

핵심은 강화학습(RL)으로 실제 코딩과 터미널 작업을 반복 수행하게 훈련한 점이에요. 개발팀은 과제를 맞혔는지뿐 아니라 필요한 도구를 얼마나 효율적으로 썼는지도 보상에 반영했어요.

### 성능

| 평가 | 기본 모델 | 어댑터 적용 |
|---|---|---|
| SWE-벤치 프로 고난도 51개 과제(추론 모드 끔) | 39.2% | 64.7% |
| 터미널-벤치 2.1 | 39.5% | 55.8% |
| SWE-벤치 프로 도구 호출 중앙값(둘 다 푼 과제) | 59회 | 23회 |
| 터미널-벤치 2.1 도구 호출 중앙값 | 18회 | 8회 |

어댑터 모델은 추론 모드를 끈 상태로도 기본 모델의 최고 추론 설정과 비슷한 성공률을 냈고, 이 비교에서 과제당 생성 토큰 중앙값은 약 4.5분의 1로 줄었다고 해요.

### 부정행위 방지와 배포

모델이 벤치마크 정답을 직접 찾아보거나 테스트를 조작해 보상을 얻지 못하도록 '세이프에이전츠(safeagents)'를 적용했어요. 모든 도구 호출을 규칙 기반으로 검사하고 부정행위 가능성이 있는 요청을 막는 방식이에요. 어댑터는 아파치 2.0으로 허깅페이스에 공개됐고, vLLM·llama.cpp 등으로 기존 큐원3.8-27B에 어댑터를 얹어 쓸 수 있어요.

허깅페이스는 하나의 기본 모델에 에이전트별 어댑터(파이, 오픈코드, 헤르메스 등)를 붙여 다양한 개발 작업에 쓰는 접근도 제시했어요. 다만 수치는 개발팀 자체 평가이고 파이 환경에서 과제당 한 번 시도로 쟀기 때문에, 다른 에이전트 환경이나 조건에서도 같은 향상이 나오는지는 추가 검증이 필요하다고 기사는 짚어요.
