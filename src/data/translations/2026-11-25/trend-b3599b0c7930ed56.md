### 무엇인가요

Cosmos 3 Nano는 텍스트와 이미지 등을 입력받아 영상을 생성하는 월드 파운데이션 모델로, 피지컬 AI 개발에 쓰여요. 이 글은 대부분의 가중치를 시스템 RAM에 두는 스트리밍 어댑터로 VRAM이 12GB뿐인 GPU에서도 모델을 돌리는 방법을 설명해요.

### 메모리 오프로딩 기법

- **가중치 스트리밍**: 지금 필요하지 않은 가중치는 BF16 또는 FP8로 시스템 RAM에 두고, 트랜스포머 블록을 필요할 때마다 GPU로 옮겨요. 행렬 연산과 어텐션은 모두 CUDA에서 돌아가요.
- **그룹 오프로딩 확장**: Diffusers의 기본 그룹 오프로딩을 확장해 이해(understanding) 경로와 생성 경로를 함께 조율해요.
- **이해 컨텍스트 재사용**: 생성 중에는 조건이 고정되므로 이해 컨텍스트를 한 번만 계산해 디노이징 스텝마다 다시 써요. 디노이징 중 FP8 정밀도가 바뀔 때만 다시 계산해요.
- **가이던스용 블록 공유**: 분류자 없는 가이던스에서 분기마다 가중치를 옮기지 않고 스트리밍한 블록을 재사용해요.
- **전송 겹치기**: GPU 여유가 있으면 현재 블록을 계산하는 동안 다음 블록을 미리 올려요.
- **단계별 관리**: VAE 디코드와 안전 검사는 따로 처리하고, 제약이 큰 카드에서는 메모리 효율 VAE 실행을 써요. 12GB GPU의 720p Transfer처럼 무거운 요청은 저메모리 모드로 자동 전환돼요.
- **대가**: 시스템 RAM과 PCIe 대역폭을 더 요구하고, 대화형 용도는 아니며, 추론 중 디스크에서 직접 가중치를 스트리밍하지는 않아요. 로딩에는 빠른 SSD가 도움이 돼요.

### 실행 방법

저장소를 받아 `cosmos-framework/packages/diffusers-cpu-offloading`에서 `uv pip install '.[benchmarks]'`로 설치한 뒤, `cosmos3_streaming`의 `build_pipeline`으로 `nvidia/Cosmos3-Nano`를 `StreamingConfig`와 함께 불러와요. 예제는 189프레임, 1280×720, 24fps, 디노이징 35스텝, 가이던스 6.0으로 영상을 만들고 `export_to_video`로 저장해요. 12GB에서 빠르게 반복하려면 480×848이나 240×432를 권해요. 같은 파이프라인으로 `image=`를 넘기면 이미지→영상, `video=`와 조건 프레임 인자를 넘기면 영상→영상이 되고, `enable_sound=True`로 소리, `CosmosActionCondition`으로 액션, `control_videos`로 제어 기반 Transfer를 쓸 수 있어요. FP8 체크포인트는 `revision="fp8"`과 `checkpoint_precision="fp8"`로 불러오는데, 처음과 마지막 세 스텝은 W8A16, 중간 스텝은 W8A8을 쓰고 어텐션은 BF16 SDPA로 남아서 파이프라인 전체가 FP8은 아니에요.

### 하드웨어와 측정값

환경은 리눅스, Python 3.12, CUDA를 켠 PyTorch 빌드예요. 테스트한 소비자용 GPU 호스트의 시스템 RAM은 약 128GB였는데, 글은 이것이 측정된 최소치는 아니라고 밝혀요. 권장 시작 해상도는 12GB가 240p나 480p, 16GB가 480p(720p는 자동 메모리 관리로 가능), 24GB는 더 여유롭고, 32GB가 720p BF16에서 가장 좋은 측정값을 보였어요.

텍스트→영상 기준 주요 수치는 이렇게 나왔어요. RTX 5070(12GB)의 1280×720은 BF16 2,624.9초·피크 9.94GiB, FP8 2,235.7초·9.16GiB였고, 848×480은 849.5초, 432×240은 207.6초였어요. RTX 5080(16GB)은 720p에서 1,594.4초·11.92GiB, RTX 4090(24GB)은 1,052.2초·16.56GiB, RTX 5090(32GB)은 1,016.7초·18.22GiB였고 432×240에서는 122.9초였어요. RTX 5070의 720p 모달리티별로는 이미지→영상 2,655.3초, 영상→영상 2,655.8초, 가드레일을 끈 Transfer(30fps 121프레임)가 4,834.9초였어요. 640×480 액션 생성은 BF16에서 약 64~66초였어요.

> 이 수치들은 특정 호스트에서 한 번 측정한 값이고 통제된 GPU 순위나 BF16 대 FP8의 다중 시드 비교가 아니며, 지연은 하드웨어와 소프트웨어 버전, 안전 설정에 따라 달라져요.

체크포인트는 Hugging Face의 `nvidia/Cosmos3-Nano`와 그 fp8 브랜치에 있고, 코드는 Cosmos-Framework 오프로딩 패키지, 벤치마크 안내는 같은 패키지의 `benchmarks/README.md`에 있어요.
