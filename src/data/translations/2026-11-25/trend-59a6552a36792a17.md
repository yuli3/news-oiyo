### 무엇인가요

Semantic governance policies는 Gemini 플랫폼의 프리뷰 기능으로, 에이전트가 제안한 도구 호출을 실행 전에 하나하나 확인해요. 호출이 통과하려면 두 가지 검사를 모두 넘어야 해요. 하나는 사용자가 평이한 문장으로 쓴 규칙이고, 다른 하나는 사용자의 원래 요청이에요. 글은 권한만으로는 부족하다고 지적해요. 권한은 에이전트가 무엇에 접근할 수 있는지를 정할 뿐, 특정 호출이 조직의 규칙에 맞는지는 말해 주지 않기 때문이에요. 검사는 에이전트 밖에서 돌아가므로 모델이 자기 지시문이나 설득력 있는 사용자, 문서에 삽입된 텍스트에 넘어가도 검사를 무력화할 수는 없어요.

### 동작 방식

- 에이전트의 이그레스를 Agent Gateway로 보내면, 게이트웨이가 에이전트와 모델 사이에 자리해요.
- 모델이 도구 호출을 돌려주면, 응답이 에이전트에 닿기 전에 게이트웨이가 정책 엔진으로 보내요.
- LLM 심판이 지금까지의 대화, 에이전트의 시스템 지시와 도구 설명, 그리고 정책에 비춰 호출을 평가해요.
- 통과하면 응답이 그대로 전달되고, 실패하면 도구 호출을 포함한 응답 전체가 설정 가능한 거부 메시지로 대체돼 호출이 실행되지 않아요.
- 판정과 심판의 근거는 사용자 프로젝트의 Cloud Logging에 남아요.
- 텍스트만 있는 응답과 스트리밍 응답은 평가하지 않아요. 사용자 의도 검사는 정책 없이도 기본으로 켜져 있어요.

### 정책 예시

대표 예시는 재무 담당 에이전트에 정책 하나를 걸어 둔 경우예요. 실적 발표 전 미공개 분기 실적은 @example.com 주소로만 보낼 수 있고, NDA나 급한 사정과 무관하게 외부나 개인 주소로는 절대 보낼 수 없다는 내용이에요. 결과는 이렇게 갈려요.

- 내부 컨트롤러에게 실적을 메일로 보내는 호출은 **허용**됐어요.
- 투자자에게 보내면서 개인 Gmail을 참조에 넣은 호출은 **정책으로 거부**되고 호출 전체가 차단됐어요.
- 문서에 숨겨진 지시 때문에 파일을 삭제하려는 호출은 사용자가 요청한 적이 없어 **의도 검사로 거부**됐어요.

글에는 다른 예시도 나와요. 승인이 모두 모인 뒤에만 청구서를 제출하게 하는 규칙, 80달러 이하 환불만 허용하는 지출 한도, 이력서 요약은 에이전트가 하되 채용·불합격 결정은 사람이 내리게 하는 규칙이에요. 정책은 에이전트의 모든 도구에 걸 수도 있고 특정 도구 하나에만 걸 수도 있으며, 도구 파라미터를 참조할 수 있어요. 구글 클라우드 콘솔이나 gcloud CLI로 만들고 거부 메시지도 직접 정할 수 있어요.

### 지연과 비용

글에는 지연이나 가격 수치가 없어요. 다만 판정마다 심판이 쓴 토큰이 로그에 남아서 사용량을 추적할 수 있어요. 제안된 도구 호출마다 LLM 판정이 끼어들기 때문에 호출당 처리 시간이 더 붙는다고 보는 것이 맞지만, 글은 그 폭을 수치로 밝히지 않았어요.

### 제공 상태

Semantic governance policies는 Gemini 플랫폼에서 프리뷰이고, 현재 지원되는 정책 적용 지점은 Agent Gateway뿐이에요. 지원 모델 API는 Gemini API, Anthropic Messages API, Gemini 플랫폼의 Claude 모델, 그리고 vLLM 같은 자체 호스팅 서버를 포함한 OpenAI 호환 Chat Completions API예요. 드라이런 모드를 쓰면 무엇이 거부될지 차단 없이 로그로만 확인할 수 있어요. 글은 LLM 판정이 확률적이어서 결과가 달라질 수 있다며, 드라이런으로 먼저 검토하고 다른 통제 수단과 함께 쓰라고 권해요.
