GitHub 저장소 README를 옮겼어요. 코드는 거의 없고 대부분 마크다운 파일이에요.

### 왜 만들었나

개발을 못 하는 **B2B 영업 담당자**가 두 달 동안 Claude Code에 메일, 일정, 거래처 기록을 맡기면서 남은 구조만 추렸대요.

처음엔 `CLAUDE.md` 한 장에 다 적었는데, 틀릴 때마다 한 줄씩 넣다 보니 금방 길어졌고, **길어질수록 앞쪽 규칙만 지키고 뒤쪽은 놓쳤대요.** 이 뼈대는 그 문제를 풀려고 바꿔 온 결과예요. GeekNews 글에서는 지난번 Ask GN에서 받은 조언(크기 상한, 같이 여는 파일은 합치기, 안 지켜지는 규칙은 훅으로)을 반영했다고 밝혔어요.

### 구성

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 매번 필요한 규칙만, 크기 상한을 둬요 |
| `rules/` | 일 종류마다 규칙 파일 하나 |
| `rules/_index.md` | "이 일 하기 전엔 이 파일을 연다"는 표 |
| `rules/example-mail.md` | 예시: 메일 규칙 |
| `handoff.md` | 대화방이 여러 개일 때 방끼리 소식을 나누는 공지판 |
| `check-size.mjs` | `CLAUDE.md`가 상한을 넘으면 경고하는 훅 |

### 지키게 만든 규칙 세 가지

1. **없다고 말하기 전에 본 범위를 같이 써요.** 어디를, 어떤 기간으로, 무슨 이름으로 찾았는지요. 범위를 못 쓰면 '확인 안 됨'이라고 써요.
2. **끝났다고 하기 전에 원래 화면에서 다시 열어요.** 보낸 편지함, 저장한 파일을 다시 열어 본 결과만 보고해요.
3. **되돌릴 수 없는 일은 초안에서 멈춰요.** 메일 발송처럼 한 번 나가면 못 고치는 일만 사람이 눌러요.

### 쓰는 법

1. 이 폴더를 작업 폴더에 복사해요.
2. `CLAUDE.md`의 빈칸을 내 일에 맞게 채워요.
3. 틀린 일이 생기면 `CLAUDE.md`가 아니라 `rules/`의 해당 파일에 한 줄을 고쳐요.
4. `hooks/check-size.mjs`를 `settings.json` 훅에 걸어 두면 `CLAUDE.md`가 길어질 때 알려 줘요.

### 운영 원칙

- 규칙을 넣어도 계속 어겨지는 줄은 **그 줄 자체가 문제**예요. 지우거나 훅으로 막아요.
- 두 규칙 파일을 항상 같이 열게 되면 합치고, 한 파일 안에 반대되는 지시가 생기면 나눠요.
- 프롬프트로 안 지켜지는 건 훅처럼 **매번 자동으로 도는 장치**로 옮겨요.

작성자는 일하는 방법과 AI에게 일을 맡기며 배운 것을 브런치에 연재하고 있대요.
