Kyle Kukshtel의 글 "Your Game Is A Harness"(2026-09-12 Indie Rodeo 발표를 글로 옮긴 것)의 앞부분부터 하네스 개념 소개까지 읽고 옮겼어요. 뒤쪽의 구체적 구현 사례는 다루지 못했어요.

### 들어가며
글쓴이는 이 글이 AI가 아니라 100% 사람이 썼고, 발표 슬라이드만 참고했다고 밝혀요. 트위터용 원샷 데모가 아니라 하루 8시간, 주 5일 하는 **실제 게임 개발**에서 LLM을 쓰는 이야기를 하고 싶대요.

그는 무드보드 사이트 mood.site를 ChatGPT 웹에 코드를 복붙하며 만들면서 LLM에 입문했어요(약 2–3주 밤 시간, 총 20시간 정도). Claude Code 이후로는 웹 스택에서는 LLM이 못 하는 게 거의 없다고 느낀대요.

### "LLM은 게임에 약하다"
그런데 웹이 아닌 게임 작업에 쓰면 매번 무너졌어요. 이유로 꼽는 건 이래요.
- 웹 프로젝트는 고품질 공개 소스가 많지만, 게임은 학습 데이터가 몇 자릿수 적을 거예요.
- 게임에는 **코드가 아닌 것**이 많아요. 에셋, 씬, 수많은 시스템 등 코드로 쉽게 표현되지 않는 것들이요.
- Three.js 원샷 게임이 유행하는 건 모든 걸 코드(박스형 프리미티브)로 표현할 수 있어서인데, 그래서 작가적 개성 없는 'slop'이 되기 쉽다고 봐요.

결국 게임의 핵심 요소가 LLM에 불투명하고, 그걸 조작해야 하는 작업에서 LLM이 넘어진다는 거예요. 즉 LLM은 **기본 상태에서는 게임을 읽는 데 구조적으로 약해요**.

### LLM 기초와 컨텍스트 오염
- 프롬프트는 시스템 프롬프트, 어시스턴트 프롬프트, 사용자 프롬프트로 나뉘고, '컨텍스트'란 대개 사용자·어시스턴트 부분에 쌓인 토큰 수를 말해요.
- 한 세션 안에서는 이전 메시지가 매번 다시 제출돼요. 앞사람 말을 다 반복하고 자기 말을 덧붙이는 놀이와 비슷해요.
- 그래서 앞쪽에 '나쁜' 내용이 있으면 계속 새 작업에 영향을 주는 **컨텍스트 오염**이 생겨요. 이를 다루는 게 '컨텍스트 엔지니어링'이에요.

글쓴이는 LLM이 게임을 잘 다루게 하는 건 게임이나 LLM의 본성 문제가 아니라 **컨텍스트 문제**라고 정리해요.

### 하네스
게임에는 표준 도구가 사실상 없어서, 에이전트가 작업물과 일하게 만드는 '하네스' 개념이 중요해져요. 하네스는 예상 입력에 대해 에이전트가 취하는 정해진 행동 패턴이고, Claude Code도 하나의 하네스예요. 브라우저 반복, 텔레메트리, 프로파일링, 티켓·문서 작업까지 묶을 수 있어요.

하지만 기존 하네스들은 **게임 자체와 대화하지 못해요**. LLM에 보이는 건 작성된 코드뿐이니까요. 필요한 건 게임 속 여러 요소를 LLM이 다룰 수 있는 형태로 바꿔, 게임이라는 블랙박스를 열고 더 많은 부분을 LLM이 직접 다룰 수 있게 하는 것이라고 말해요.
