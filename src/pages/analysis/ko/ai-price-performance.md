AI를 고를 때 가격표와 성능 순위를 나란히 놓으면 답이 나올 것 같아요. 그런데 월 구독료는 앱의 이용 조건이고, API 가격은 사용량에 따른 청구 조건이에요. 벤치마크 점수는 정해진 시험의 결과죠. 셋을 한 줄로 섞으면 저렴한 모델을 찾고도 실제로는 일을 더 오래 할 수 있어요.

이 글은 공식 문서와 평가 방법론을 읽고 정리한 선택 가이드예요. 최신 모델의 종합 순위를 매기거나 직접 제품을 돌려 본 성능 실험은 아니에요. A·B 비용 비교는 가상 사례이고, [공식 API 가격표](#official-prices-title)는 확인 날짜와 조건을 따로 밝혔어요.

## 1. 구독 상품, 모델, API를 먼저 나눠 봐요

같은 모델 이름을 써도 채팅 앱과 코딩 에이전트, 직접 호출하는 API는 이용 방식이 달라요. 앱에 검색이나 파일 편집이 붙어 있으면 모델만의 답변 능력보다 그 연결이 작업 결과를 바꿀 수도 있어요. 비교 대상의 이름 옆에 **플랜·모델 버전·허용 도구·확인 날짜**를 적는 것부터 시작하세요.

“구독과 API는 무조건 별개”라고 외우는 것도 지금은 정확하지 않아요. 앱의 이용 한도, 직접 API 호출의 종량제 요금, 플랜에 명시된 API 크레딧이나 승인된 연동 권한을 따로 확인해야 해요. 예를 들어 [Claude 공식 가격표](https://claude.com/pricing)는 일부 플랜의 API 크레딧을 안내해요. 포함 조건까지 읽어야 실제 혜택을 알 수 있어요.

OpenAI의 [Sign in with ChatGPT 문서](https://developers.openai.com/siwc/quickstart)도 로그인 권한과 ChatGPT 플랜을 사용하는 API 권한을 구분해요. 로그인 버튼이 있다는 이유만으로 아무 서비스나 사용자의 구독을 무제한 사용할 수 있다는 뜻은 아니에요. 앱의 자격, 사용자가 승인한 범위, 적용 조건을 확인해야 해요.

## 2. API 가격표는 한 개의 단가가 아니에요

[OpenAI 가격 문서](https://developers.openai.com/api/docs/pricing)는 입력·캐시·출력과 도구 비용을 나눠요. [Claude API 가격 문서](https://platform.claude.com/docs/en/about-claude/pricing)는 캐시 쓰기와 읽기, 일반 호출과 배치 처리를 구분해요. [Gemini 가격 문서](https://ai.google.dev/gemini-api/docs/pricing)에서는 모델별 무료·유료 지원, 추론 토큰이 포함된 출력 항목, 캐시와 검색 조건을 확인할 수 있어요.

따라서 “입력 100만 토큰이 얼마인가”만 비교하면 빠지는 항목이 생겨요. 모델·문맥 길이·처리 방식·지역·프로모션 기간을 맞춘 뒤, 실제 청구 항목을 계산해야 해요. 캐시도 적중한 부분에만 해당 조건을 적용하세요. 캐시 쓰기나 저장 비용이 있는 상품에서는 할인된 읽기 단가만 쓰면 비용을 적게 잡게 돼요.

기본 계산은 각 시도의 **미캐시 입력 비용 + 캐시 관련 비용 + 청구 출력 비용 + 도구·저장 비용**을 합산하는 거예요. 사용량에 재시도가 이미 포함됐다면 다시 더하지 말고, 앞 항목에 포함되지 않은 비용만 추가하세요. 추론 토큰이 이미 청구 출력에 들어 있다면 이것도 다시 더하지 마세요. 한국어 글자 수를 토큰 수로 고정 환산하는 대신 실제 사용량 기록을 확인하는 편이 낫고요.

## 3. 저렴한 호출과 저렴하게 끝낸 작업은 달라요

편집부가 제안하는 비교 단위는 **총비용 ÷ 사전에 정한 기준을 통과한 결과 수**예요. 다음 예시는 검수 시간이 선택을 어떻게 바꾸는지 보여 줘요. A와 B는 실제 제품이 아니며, 각 100번 시도하고 재시도는 하지 않았다고 가정했어요. 검수는 통과 결과에만 수행하고, 실패 결과는 폐기한다고 단순화했어요.

A는 호출료만 보면 싸지만, 이 가정에서는 B가 기준을 통과한 결과를 더 적은 총비용으로 제공해요. 반대로 검수가 거의 필요 없거나 B의 결과가 우리 기준을 만족하지 않는다면 결론도 바뀌겠죠. 위 예시는 비싼 모델이 항상 낫다는 증거가 아니에요.

실무에서는 실패를 판별하는 시간, 재시도, 결과 수정, 대기, 연동 개발비도 필요에 따라 포함하세요. 구독의 월 고정비를 작업별로 나눌 때는 배분 기준을 적어 두고요. 로컬 모델도 전기·장비·운영 시간이 드니 토큰 청구액이 없다는 이유로 총비용을 0으로 두지는 마세요.

## 4. 벤치마크는 작업을 고르는 지도이지 보증서가 아니에요

[Artificial Analysis의 평가 방법론](https://artificialanalysis.ai/methodology/intelligence-benchmarking/)은 여러 시험을 종합해 모델을 비교해요. 이 점수가 높다는 사실만으로 한국어 행정 문서, 음악 생성, 계약 검토에서도 최고라고 결론낼 수는 없어요. 먼저 시험이 어떤 능력과 언어를 측정하는지 확인해야 해요.

[SWE-bench Verified](https://www.swebench.com/verified.html)는 사람이 검토한 500개 사례를 사용해요. 코딩 결과를 볼 때는 모델 이름뿐 아니라 에이전트 구성, 도구, 시도 횟수와 평가 환경도 봐야 해요. 서로 다른 시스템이나 시험 버전의 점수를 그대로 모델의 순수 능력 차이로 읽지 마세요.

속도도 마찬가지예요. 출력 토큰이 빨리 나와도 답변을 시작하기까지 오래 기다리거나 여러 번 수정해야 한다면 작업은 늦게 끝나요. [Artificial Analysis 속도 방법론](https://artificialanalysis.ai/methodology/performance-benchmarking)이 구분하는 첫 토큰 지연과 출력 속도 등을 참고하되, 실제 비교에서는 **입력부터 검토 완료까지 걸린 시간**을 별도로 재는 게 좋아요.

이 표는 분야별 우승자를 정한 결과가 아니에요. 공개·자체 자료로 작은 시험을 설계할 때의 질문이에요. 법률이나 금융의 개인별 결정을 대신하는 추천으로 사용하면 안 돼요. 민감한 계약·계정·개인정보를 외부 서비스에 넣기 전에는 허용 범위와 데이터 조건을 먼저 확인하세요. 무료 티어가 있다는 사실은 민감정보 처리 허가가 아니에요. [Gemini 약관](https://ai.google.dev/gemini-api/terms)처럼 요금표와 연결된 데이터 조건도 함께 읽어야 해요.

## 6. 결제 전, 반복하는 작업 하나로 좁혀 보세요

먼저 자주 하는 작업과 통과 기준을 한 문장으로 적어 보세요. 예를 들면 “이 PDF에서 표를 옮기되 단위와 합계가 맞고, 사람이 원문 위치를 확인할 수 있어야 한다”예요. 그다음 접근 가능한 후보 몇 개에 같은 자료를 주고 오류·수정 시간·비용을 기록하세요. 공개할 때는 제품 버전과 도구, 날짜, 시도 횟수, 실패 사례도 남기고요.

결론이 “기존 무료 도구로 충분하다”거나 “이 작업은 사람이 직접 하는 편이 낫다”여도 괜찮아요. 더 높은 순위나 더 큰 구독이 아니라, **우리의 기준을 만족하는 결과를 감당할 비용과 시간 안에 얻는지**가 선택의 기준이에요.

### 확인 범위와 출처

2026-10-15에 연결된 공식 문서와 평가기관의 방법론을 확인했어요. 개별 서비스의 전 요금제·모델을 전수 검증한 가격표는 아니며, 결제 직전에 해당 상품의 최신 조건을 다시 확인해야 해요. 가상 비용 계산과 업무별 확인 질문은 OIYO의 편집 예시이고, 직접 사용 실험이나 전문 분야의 적합성 검증을 대신하지 않아요.
